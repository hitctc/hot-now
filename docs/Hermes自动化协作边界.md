# Hermes 自动化协作边界

> 本文是 HotNow 与 Hermes 之间控制面、队列和创作交付边界的权威说明。Hermes 内部阶段、运行时 Skills 和实现版本仍以 `/Users/tc-nihao/.hermes/scripts/prd/公众号写作管线-任务与Skills协作索引.md` 为准。

## 1. 真源与职责

Hermes 是以下业务的唯一编排、状态、队列、计划、重试和告警真源：

- 素材采集后的基础评分与账号适配评估；
- 自动长文与短内容写作；
- Luna 图片生成与文章闭环；
- 日报、提醒和邮件通知；
- 自动任务模式、阶段许可、周期槽位和终态历史。

HotNow 只负责：

- 保存和展示素材、成品及轻量追踪信息；
- 代理人工控制、写作、图片和监控请求；
- 轮询并展示 Hermes 返回的队列、周期、失败原因和成品入口；
- 在既有报告、邮件和时间线计时器执行前查询 Hermes 阶段许可。

HotNow 不得创建平行自动化队列、重试器、计划、账号适配判断或图片任务状态机。素材入库只写展示数据，不得在 HotNow 本地自动创建评估或写作任务。

### 页面详情读取

共用成品详情的弹窗与遮罩开关动画显式禁用，避免退场遮罩继续阻挡表格重开；仅HotNow前端展示配置，不改Hermes队列或任务。未保存内容仍经原关闭保存流程，失败保留稿件；不强关、不提前重放、不全局禁用其他弹窗或专注模式动画。

HotNow长短成品/素材入口共享详情读取守卫：点击即加载、切换或关闭淘汰旧GET；无当前详情身份的迟到保存通知只刷新列表，不淘汰正在打开的GET。只管理页面读状态，不取消后台任务或原关闭保存、不重放模型/写作/发布。移动数据表格只改前端外侧宽度，PC与原业务接口不变。

### 短素材首次来源榜位

Hermes热搜采集在原列表过滤前记录原位置及榜单名称、采集时间，保存于既有extra.source_ranking，通过原素材POST的sourceRanking交接；热门视频列表只记位置，编辑精选不标排名。HotNow只将快照随首次入库存入原raw_payload_json，幂等回推不更新；列表只提取小快照，不传完整原始包或增加查询。短素材来源第二行及短成品标题顶部显示同一首次时段榜位，短成品不显示旧模式；历史缺失不推断、RSS不编造，长内容展示不变。采集去重/限额/时间戳/源游标、评分、事实门禁和唯一队列均不变，不采当前榜单回填历史。

### 短素材评分状态

短素材score仅承载Hermes选题分，默认75入选，实际读取short_content_score_threshold；通用基础补评与爆文正常/全量重评均限定article，并在模型执行前防御性排除短素材。HotNow短素材表、详情和短成品不展示爆文分/维度，短页不传爆文筛选并清除旧偏好；长素材仍按原规则。日报继续包含短素材，短素材仅复用配置选题门槛，长素材沿用72基础分/50爆文分，不新增评分调用。

Hermes正常评分后以原状态动作回写ready/skipped、selectionScore和完整停止详情；onlyIfPending仅推进平台pending，原子同步真实分数，避免入库仅补空而保留通用旧分。写作事实或质检停止用onlyIfWritable仅同步pending/ready/queued/writing，保护人工done/excluded/skipped/failed等终态；同步失败交原技术恢复预算，不冒称回写成功。原因分别来自去重、评分理由、事实检查和末次质检反馈，不将评分意见混入原摘要，不新建队列。历史无理由明确显示未记录，有分仍pending提示待同步，不批量改历史或自动补写。

### 发布稿语境不可用风险确认豁免

- Hermes 保留完整取证包用于审计及独立质检；写作/审改/附属文案只接收隐藏采集时间、内部取证说明的写作视图，原文证据、真实适用范围和不确定性不截断。`detail`/长摘要仅作找原文的线索，搜索结果页不升级成原文；旧 `supported` 包也重新检查来源等级。政策/全国假期安排必须核对相应年份和官方依据，不能改写成一篇讨论本稿核验失败的文章。
- 短稿复用既有评分调用，要求独立 `publication_check`（`reader_facing`、带字段路径和片段的 `process_leaks`），高分不能抵消语境污染；缺少完整回执是技术失败。最终交付覆盖标题、正文、导语、评论、作者回复、拓展及标签；旧质检/终稿缓存使用新策略键，不沿用旧通过结果。
- 长文在受限编辑/审改回退后先做窄规则检查；Step8 拼装后新增一次既有评分模型的完整发布语境复核。回执以全部发布字段的指纹保存在原检查点，输入/策略变化重新检查，重试不重复已成功的同输入请求，不新增队列或无限重试。
- `stepTrace.meta.publicationCheck` 保存 `reader-facing-v1`、`passed`、问题字段、正文/标题指纹；附属文案不是实际推送字段时，不能误伤已修正的正式正文。强制稿可带风险交付编辑，但当前正文/已选标题匹配专项否决版本时，HotNow 服务端不可用 `riskConfirmed` 放行。改稿不沿用旧判断，不新增独立审核按钮。
- HotNow 同一推送核心检查实际选用标题、`humanMarkdown ?? contentMarkdown` 和提交 HTML 的文本；普通、人工、强制稿一致，拆标签/零宽字符不能绕过，在图片上传、推送日志写入及草稿创建前阻断。这里只作发布校验，不增加 HotNow 自动化编排或模型调用。
- 不按“搜索”“证据”等单词封禁，正常技术/司法报道及真实来源归属允许；固定规则与语义判断均不是百分之百准确的证明。3664 保留原稿，不批量改状态或发布，真实阅读/公众号验收见 [发布稿语境验收](./发布稿语境验收.md)。

### 短写事实不漂移

新手动/自动短写冻结 `fact_policy=source-facts-v1`，原链接正文取证、逐字引用验证和事实锚点均由 Hermes 完成；评分方向不再混入原摘要。原模型记忆、搜索摘要、旧文档未列型号不能代替核验或否定新事件，平台接入与厂商全球发布须区分。标题/正文/审改/导语等交付文字共享同一事实包，独立事实冲突或漏检不能被文笔分抵消；证据不足/核心事实不合格在原队列给出复核原因，普通文笔低分审核合同不变。交付发现正文问题共用原剩余重写预算；仅附属错误时弃用可选评论/拓展，导语回退正文完整句；标签独立核验，正常标签不得连带清空，错误标签最多补生成一次再核验，完整透传事实包。整套回退包须重新通过核验才交付，记录deliveryFactRecovery及keywordGeneration/keywordFactCheck。分析归类、条件预期与修辞不要求逐字摘抄，存在表述不能被擅自补为唯一或全称；具体数字、亲历、已发生效果仍须有据。

首步 `stepTrace.meta.factCheck/deliveryFactCheck` 保存来源、抓取时间、原文引用与指纹，HotNow只展示/存储，不创建自己的核验器、队列或状态机。旧已受理无标记任务保持恢复输入，历史文章不批量重写；长文v2、用户自由编辑及详情文案独立重生成不扩大本轮合同。3521仅在明确授权下核验并另建修复副本，不覆盖旧正文。权威任务职责仍见Hermes现役PRD。

## 2. 自动化控制面

- 自动化只有一个全局模式：`running`、`paused`、`emergency_stopped`；阶段开关独立存在。
- `paused` 只阻止自动任务；`emergency_stopped` 还会取消未开始的自动队列项；两者均不影响人工写作。
- 新控制统一使用 `/api/creative/automation/status` 与 `/api/creative/automation/control`。
- 旧 `/api/creative/automation/:kind/enabled` 只作为兼容代理，不得扩展新的平行开关语义。
- HotNow 的 scheduler 只能把 Hermes 阶段许可作为执行前门禁，不得保存第二套自动化状态。

## 3. 写作队列与周期

### 人工优先与兼容入口

当前已接入标题、标签、摘要、评论、作者拓展、图片提示词和人工 Luna 单图：复用 Hermes 唯一队列，人工短操作优先于人工长任务，再优先于自动任务；同级先进先出。成功模型返回保存后才能让位，图片生成与上传各有检查点，正文已入库后只续图片，不重写正文。旧同步详情入口在 HotNow 代理中改为返回 `202` 编号，Hermes 旧同步文本 HTTP 入口返回 `410`，不能绕过队列。

任务取消只作用于指定编号，执行中不强杀当前请求。失败和取消的已有结果以私有文件保留，状态接口不返回正文，已鉴权的只读结果接口允许页面查看；模型和本地能力标记与任务状态分开。版本冲突停止写回，不重读新稿合并；检查点保存失败暂停模型执行，不伪称恢复成功。排队不设十分钟失败期限，实际模型执行超时独立处理。

详情文案、导语和日报提交支持预存 `requestId`：浏览器先保存请求编号，Hermes 将请求映射和任务在同一次原子落盘中保存；活动去重返回的编号也绑定新请求，终态后保留脱敏收据，历史列表淘汰或重启不产生第二次生成。收据保留 30 天，过期编号直接拒绝重放；浏览器时钟偏差超过五分钟可能被拒绝。浏览器禁用存储时仅保证当前页面内复用，不保证跨刷新。本文案请求合同不扩大到素材创建或旧图片 Provider 入口。

日报 `/api/generate-digest` 返回 `202` 和编号，`GET /api/generate-digest/status` 只观察原任务。门户默认素材日期由首次请求编号时间按北京时间固定，响应丢失后跨零点重放不换日期；发布日期与同日期覆盖规则保持不变。手动日报属于人工长任务，自动日报检查 `daily_digest` 阶段；素材快照、分类和成功封面结果可复用。正式 CLI 只向常驻 API 提交，不创建第二 worker；`--dry-run` 是维护预览，不推送，但仍可能调用文本模型，未作为全队列业务入口迁移。导语回调携带生成时的 `expectedUpdatedAt`，版本变化拒绝写回；已交付的同一文本幂等成功。缺少原版本的旧检查点保留结果但禁止猜测新版本回写。下一模型请求前遇到冷却归队释放资源，取消优先于冷却；取消正文已交付任务保持素材 `done`。

### 内容阻断后的人工强制重写

- `POST /api/creative/write-queue/force-rewrite` 经会话鉴权代理到 Hermes 同名接口；传原 `taskId`、预存 `requestId` 和 `confirmed:true`。Hermes 判定内容阻断资格，不允许技术失败、取消、紧急停止或交付故障绕过。短素材缺少可靠关联时拒绝，不猜本地/平台编号。
- 强制重写建立新的人工长/短任务，复用唯一队列、当前管线和成功检查点，不改原任务、旧成品或自动计划。模型/额度、存储和调度错误保留原处理；正常任务仍执行原内容硬门禁。
- 人工例外仍做取证、事实核验和质检，未通过项保留为风险而非伪造通过。长文没有合格读者方案时采用明确待核实的风险分析任务；无证据骨架不伪造已确认事实。短文初检未过沿用不进入 human-writing 的原规则，交付仍核验。
- 成品使用既有 `needsManualReview/manualReviewReason/manualReviewReasons` 保存「人工强制重写 · 待人工审核」、原任务原因及本次风险，状态为 `needs_review`。强制稿不要求额外审核/标记操作；内容齐全后在原推送浮窗确认一次风险，服务端校验 `riskConfirmed:true`。推送状态更新不清除风险，不自动推送公众号。
- 同一原任务交付以素材与首项原任务审计标识恢复既有编号，返回 `201 created:false`，避免响应丢失后重复新建；其他任务仍允许建立新稿。新请求受原 30 天收据合同保护，不增加队列、schema 或 Skill。浏览器/真实模型未验收项见[专项验收](./强制重写与队列浮窗验收.md)。

- 人工长短写作、自动短内容候选和详情手动重生成导语都进入 Hermes 现有全局文章队列；导语任务使用人工高优先级，不在 HTTP 请求中等待 Luna 租约。
- 人工短内容任务携带 HotNow 素材 ID，使用高优先级；短内容素材页“自定义写作”也只创建 `short_content` 素材，通过 Hermes `/api/short/write` 保存指定输入并由短内容管线回推短成品，不得调用长文 `/api/write-article`，也不能改写其他待写素材。自动短内容使用普通优先级，并受 `short_write` 阶段门禁控制。
- 自动短内容只消费当前采集批次，不自动补写历史 `ready` 素材；短内容采集和短内容写作是两个独立阶段。逐篇模式在两轮采集之间继续消费同一批次，不要求每篇重新采集。
- Hermes `/api/short/write-schedule` 是短写调度展示真源，返回当前候选顺位、待确认素材、最近被新批次替换记录，以及从唯一写作队列读取的短写任务状态摘要；队列任务按 `source_external_id` 与 HotNow 素材关联，展示排队位置、写作阶段、完成成品或失败/停止原因。HotNow 仅代理并展示，不推算预计时间或建立平行状态机。没有可追溯任务时只说明当前批次外且未找到投递记录，不推断历史从未入选；候选替换历史仍有界保留。
- 队列终态历史由 Hermes 持久化；HotNow 只展示，不以客户端历史推导数据库统计。
- 短成品重复回推只有明确 `article-already-exists` 且携带正整数 `articleId` 才恢复平台关联；其他冲突和缺编号仍失败，不重新写作、不修改原成品。维护补推脚本一批出现失败即退出，保留未同步素材供下次维护；不改变现役自动批次交付。
- 逐篇文章推送次数与历史排除明确的日报记录，未分类旧行沿用原口径；日期带仍只计明确文章成功记录。
- 队列素材入口只使用 HotNow 平台素材编号。Hermes 自动短内容摘要在缺平台编号时提供 `source_external_id`，不将本地 `item_id` 当平台编号；HotNow 只按唯一短素材外部标识或已交付成品关联补充展示编号，缺失或歧义不猜测。当前任务、排队项和历史记录的素材编号可打开同一只读详情，成品只读正文与图片限制阅读尺寸，不改变原稿、图片文件或队列行为。
- 队列日期按北京时间自然日展示。日期带文章数按成品 `created_at` 全量统计，素材数按 `collector_timestamp`、为空时回退 `created_at` 全量统计，不受分页和队列历史条数影响。
- 每轮自动长文槽位、素材锁定、候选理由、同主题去重、成功、阻断、待重试和重试耗尽结果都由 Hermes 记录。HotNow 不复制筛选条件或补投递。
- 长文周期边界由 Hermes 配置的执行时间决定，当前默认北京时间 10:00；零点不切换。五分钟复核只补空槽，定时和人工触发只执行当前快照。

- 用户确认旧配置为 60 分钟最多 6 篇，目标改为 7.5 分钟最多投递 1 篇，后续在 `/monitor` 调整。该参数是投递节奏，不是日产量、保证完成数量或模型执行超时。
- Hermes 采集后评分，按平台轮转形成候选 ID 快照，保存在 `pipeline.db` 的 `automation_short_write_state`。现有分钟 tick 在采集间隙投递；新批次替换尚未投递的旧候选，已受理任务不取消。
- 常驻唯一队列在受理锁内校验最多一项活动自动短任务及最小投递间隔；已有自动短内容排队或执行中不追加，错过不补投。人工写作与每日长文计划不受影响。
- 投递前保存请求编号；响应不明时跨周期、换批次或重启仍复用原编号，任务及收据原子保存，不重复模型调用。只保留候选 ID 和请求元数据，不复制业务 worker 或正文。
- 监控分为“长内容计划”和“短内容节奏”；逐篇模式取消每轮数量的独立编辑，小数分钟范围为 1–1440。分钟 tick 和共享资源可能延后投递，不保证精确 450 秒开写。
- 滚动发布时 `shortWritePacingSupported` 表示后端具备能力，`shortWriteMode` 区分旧批量与逐篇。保存新间隔才启用 `short_write_pacing_version=1`，每次数量固定为 1；旧服务未更新时页面禁止保存小数，不能误报新规则已生效。重启前先确认活动任务安全，实际切换及浏览器验收见 [收尾验收记录](./人工模型任务收尾验收.md)。

## 4. 评分与写作边界

### 科技数码与 AI 核心短写

- 现役两个 RSS 是 Juya（`juya-ai-daily`）与 AI HOT（`aihot`），不是公众号 RSS。短写保留综合热搜，在原 `short_collection` 阶段逐源交接：Juya 读取普通内容池，AI HOT 只读 `aihot-collector` 的原长素材，不新增采集源、阶段、队列或计时器。长线仍由原 AI HOT 采集器直接入库，并仅自动交接 Juya；公众号 RSS 仅保留手动/历史兼容读取。
- `raw-rss` 短方向必须传 `sourceFeed`，只排除目标方向已交接的 URL。Hermes 沿用 Juya 的 `short_rss_after_id`，AI HOT 独立保存 `short_rss_aihot_after_id`，两类编号不能混用。各源首次成功只定基线；之后升序分页，先入短素材再推进游标，重放不刷新原采集时间，失败不越过未落库编号。RSS 故障不阻断热搜。自动流程只写当批、不补历史；经用户明确授权的当天补交接用 `collect(started_at, today_only=True)` 按北京时间原采集日期过滤、保持去重键，不读写长期游标，评分与写作仍走原门禁和唯一队列。实际人工执行用 Hermes 既有鉴权 `POST /api/short/run`、仅传 `{"rss_today_only":true}`，在原 tick 锁下处理当天未完成 RSS、限定编号评分，显式回推素材状态，合格项幂等合并原候选；不覆盖热搜、待确认请求或投递间隔，不把候选合并/HTTP 202 当作成稿。执行合同以 Hermes 现役 PRD 为准。
- 来源在 `extra.source_name/source_feed` 保存，交付 RSS 原名，不伪装热搜；选题评分同一请求输出 `content_domain`（`ai/tech_digital/other/unknown`），在 `extra.content_domain` 保存，不提高分数、不降低准入门槛。沿用当批跨源事件去重。
- 当批 ready 先按平台轮转，再每两篇核心候选穿插一篇其他热点；一侧缺失就消费另一侧。仅调整自动候选顺序，不设产量配额，不更改投递间隔、人工任务优先级或指定素材。
- 新默认/auto 队列参数另冻结 `editorial_focus=tech-ai-v1`，写作请求同时识别主领域并对核心稿加入实际变化、用户影响和限制的视角，不编造体验或把宣传当验证结果；其他热点保持原策略。显式兼容规格与无该参数的已受理任务不切换提示词。
- 主写作第一步 `stepTrace.meta` 保存 `editorialFocus` 和 `contentDomain`，复用既有追踪持久化与回推，不迁移 schema。短成品摘要仅补这两个轻量字段；标题旁 AI 紫色、科技数码蓝色，不表示质检通过或推荐发布，其他/未知/历史稿不猜标签，不批量回填。验收见 [专项记录](./短内容科技数码与AI方向开发验收.md)。

### 长短双线与统一短写

- 长文保留v2八阶段、读者价值和核心判断证据门禁；短内容保留独立选题、事实复盘、质检与有限重写。两线复用既有模型入口、唯一队列、检查点、human-writing与资产工具，不合成万能管线或同一评分。
- 新默认/auto短写任务将 `writing_strategy=brief-v1` 保存为内部队列参数，并在写作trace记录 `writingStrategy`；无该参数的已受理任务及显式 `tuwen/duanwen` 保留旧执行合同。外部请求仍使用原枚举；不按日期或历史form猜策略，不迁移历史schema。
- 统一短写建议120–600字、1–4处重点，按事实复杂度表达，不新增硬性字数失败条件。兼容存储列保留duanwen，但它不控制新稿文体、加粗或图片。评论/拓展使用实际交付稿最多3000字符，在质检/审改/卫生处理后生成；标签若因终稿变化失效则重新生成，失败不伪造或回填旧标签。图片提示词一条，实际生图资格、三比例代码图和触发范围不变。
- 新自动短写区分技术失败与内容不合格：前者交原队列单次恢复预算，不标记素材skipped；后者仍最多重写2次后停止。人工允许交付审核稿的原规则不变，不把两种终态合并。新任务已落稿回推失败复用成功产物/本地编号续交付，已有平台关联不重推或重复触发代码制图。
- HotNow短成品表撤销旧form分类，仅展示生成时质检分，不显示关联素材趋势；空白人工新建允许省略form，旧显式合法值保留、非法显式值拒绝，不调用模型。

- 基础评分与账号适配是两个独立阶段。HotNow 可以展示适配结果，但不提供手动账号适配入口，也不以本地适配结果阻止人工写作。
- 写作管线为 `Hermes 事实核验/写作 -> human-writing 只读终稿审改 -> 图片提示词/图片执行 -> HotNow 成品创建`。
- 初次成品创建同时接收 `contentMarkdown` 和 `humanMarkdown`；`stepTrace.meta.humanWriting` 只保存状态、模型、尝试次数、耗时、Token、版本指纹和回退原因，不能写入 Hermes 本地审改全文。
- 短内容标题参照素材原标题生成不同的新表达，不照搬或只改标点；保持事件主体、关键数字、核心吸引点和疑问结构。`human-writing` 阶段如实记录保真分，低于 80 分不阻断、不回退原标题或标记人工审核；审改/复检失败保留主写作新标题和初检合格正文，正文质检通过即可推送。主写作照搬或漏标题时由 Hermes 补生成，仍无新标题则返回技术错误。
- 短内容人工重新生成标题固定返回“最贴近原标题 / 适度压缩 / 自然口语”三类候选；历史成品不批量改写，长文标题逻辑不受影响。
- 短内容成品状态入库时归一化为平台状态：`ready -> ready_for_publish`，`draft` / `needs_rewrite -> needs_review`。质检通过后可以直接推送草稿箱，不需要额外“标记可推送”。

## 5. 正文与图片并发合同

- AI 草稿和人工发布正文分别保存；自动保存不得触发父页面详情刷新，成功响应必须同步服务端 `updatedAt`。
- 详情手动重生成导语先收口正文自动保存，再由 Hermes `/api/regen-intro` 立即返回现有队列任务 ID（`202`）；同篇未完成任务复用 ID，`GET /api/regen-intro/status` 查询终态，队列检查点保证回调重试或重启不重新生成不同导语。Hermes 生成后通过鉴权 `POST /actions/creative/finished-articles/:id/regen-intro/complete` 回调 HotNow 唯一入库点；重复回调不重复保存，页面关闭后仍完成入库。页面拿任务结果同步正文，导语已入库但正文同步失败时不能误报生成失败；短内容自动写作在终稿确定后生成导语，经 Hermes 本地成品保存后随成品回推，不在 HotNow 建立平行生成任务。
- 图片回写与正文编辑并发时，必须保留已经落库的图片 Markdown 槽位，并清理对应图片描述。
- 异步图片回写必须携带文章版本；遇到 `article-revision-conflict` 时基于最新正文重试。前端只能替换目标图片槽位，不能用旧整篇正文覆盖用户编辑。
- Luna 配图资格由 Hermes 按实际模型、触发类型和图片阶段开关判断。素材库手动写作只生成图片提示词，不随写作自动执行或排队 Luna 图片；成品详情显式触发的单图生图入口仍保留。HotNow 只提交人工意图，不直接调用模型。
- Luna 长文使用 Hermes 单一文章闭环队列；自动写作符合图片阶段资格时完成配图和回写后才开始下一篇，人工写作在正文和提示词交付后即可完成。HotNow 只展示阶段、图片进度、重试次数和最终结果。

## 6. 成品代码图片

- 长文详情手动复用三比例代码制图、下载和封面候选选择；不自动插入长文正文，不改模型生图开关，不批量处理历史文章。
- 新长文在 Step6 既有导语/摘要请求中同时生成最多三个 `codeImageKeywords`，随成品交付；漏标签不增加请求、不阻断交付。旧文可显式手动调用 Hermes 生成标签（消耗模型额度）；制图本身绝不隐式补标签。

- Hermes 自动短内容定向成品推送成功后触发 HotNow 单篇代码制图；现役人工短写交付不隐式新增制图调用，页面可以人工制作和整组重做。制图失败不阻断文章，不新增补图队列。
- HotNow 使用 SVG + Sharp 与部署字体输出 `2.5:1`、`1:1`、`3:4` 三张 PNG，仅写入 `code_image_cards` 和封面候选；新短内容不自动插入三图，正文保存也不自动补候选封面，无已有选择时默认方图，后续保留手动选择。旧稿正文和已选封面不批量调整，长文规则不变。短详情放大封面选择按钮、突出当前封面标识；不增加图片任务或改变Hermes调用。
- 标签优先读取成品 `codeImageKeywords`，再读取素材 `tags`；没有标签时不伪造内容，不输出空占位文案。
- 标题、核心判断、导语/摘要、标签或选中标题变化会把已有代码图片标记为 `stale`；普通正文段落变化不触发重做。
- 制图失败不改变文章状态；每次重做整组生成三张，只更新当前引用并保留旧文件。

渲染尺寸、排版算法、字体和测试细节见 [短内容代码制图开发方案](./短内容代码制图开发方案.md)。

## 7. 变更同步要求

以下变化必须在同一轮同步本文、HotNow 代码与测试，并更新 Hermes 对应 PRD：

- 自动化全局模式、阶段开关或兼容接口语义；
- 队列优先级、周期槽位、当前批次或终态历史语义；
- 写作阶段、运行时 Skill、轻量 trace 字段；
- Luna 资格、文章闭环或图片回写协议；
- HotNow 与 Hermes 之间的 API、鉴权、超时或错误合同。
