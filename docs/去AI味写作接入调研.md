# 去 AI 味写作接入调研

## 2026-10-15：工程实现与质量证据分开

**发布决定：用户授权先提交、推送，再部署并观察正常生产的新长短稿。独立审查和同模型对照不作为本轮发布前置条件；实际部署结果以交付报告为准，不把上线等同于已证明质量提升。**

本轮按用户要求同时优化长短内容，不再只给终稿追加去味规则。Hermes 现有写作、方案、编辑、审改、质检、标题和摘要环节统一到“准确、切题、清楚、自然”，去掉强制评论、固定事实/判断比例以及无据行动、反方或收益要求；长文允许 explain 立场和保真段落重组。

另用测试复现并修复中文紧邻数字漏检、长文编辑可增加数字或改变图片描述、空证据索引方案仍能入选，文本卫生同步数字边界。没有增加模型轮次、Skill、队列、质检分数或重试预算，没有改共享 human-writing 和 check_prose，没有批量改写历史稿。数字去重仍保守拦截，静态规则不能证明完整语义保真。

实现合同见 Hermes 现役 PRD 与[自动化协作边界](./Hermes自动化协作边界.md)。隔离替身测试只能证明规则、调用、回退和恢复行为，真实同模型同素材对照、独立阅读和稳定质量增益尚未验证。此前两轮样稿也不能补足这项证据，不把本次规则修正宣传成已证明文章质量显著提升。

下文保存原始调研和离线试点沿革，历史建议不覆盖当前实现合同。

## 后续试点决定：放开最小清理，保留事实与观点边界

用户在审阅首轮三篇样稿后明确要求更全面地处理固定词、句式和论述套路，允许超出上游白名单的最小清理范围。当前接入方向调整为“保真重编辑”：可重写句子、删除重复论述、合并或调整段落，但不得新增事实、伪造经历、改变实质观点或削弱判断条件。词表只作提醒，不再以命中固定词清单作为唯一改写理由，也不追求改动比例或禁词清零。

第二轮沿用同三篇离线稿，从词语、句子、段落、全文组织、修辞语气和作者/读者位置检查实际阅读问题。完整试点规则及前后对照保存在 `data/less-ai-tone-pilot/20261014-234659/round2/`（本地产物，不提交 Git）。原稿、第一轮与生产规则均未覆盖；当前会话模型编辑不等于 Hermes 同模型对照或生产复检。

下文是最初的上游调研，白名单最小改动、固定段落与逐字保留建议不再作为现阶段试点的约束。上游的证据局限、信息保真、Hermes 唯一编排和有限回退等结论仍有效；生产实现及其校验合同须在后续真正接入时另行更新和验证。

## 1. 结论与范围

建议借鉴 `larashero3-dotcom/lieflat-less-ai-tone` 的白名单式局部清理规则，补强 Hermes 现有终稿审改，不直接替换主写作，也不默认增加第二轮全文模型改写。

目标是提高真实读者感受到的自然度，同时守住信息量、事实准确性、作者判断和可读性。规则命中减少不等于文章质量提高，更不代表能通过某种 AI 检测器。

本轮仅完成公开仓库及本地实现的只读调研，新增本文。不安装 Skill，不执行上游脚本，不调用真实写作模型，不读取数据库、凭据或历史成品，不修改、部署生产链路。本文是建议，不是已生效的运行合同。

公开仓库核对版本：`27d29232f10124db904ca9c0536d0b67cb3b2833`。链接以下均固定到该版本，后续实施不自动跟随上游主分支。

## 2. 项目实际提供什么

- 核心是 Markdown 写作指令 `SKILL.md`，不是训练模型、独立去味服务或可直接调用的 HTTP API。[S1]
- 采用白名单式审改：只处理明确命中的规则，未命中内容逐字保留；锁定标题层级、段落顺序、列表、表格、引用及代码块；不得新增事实、删除观点或抹掉限定词。[S1]
- 11 类规则涉及翻案腔、顿号密集罗列、相邻句同构、破折号与冒号滥用、连续编号小标题、理想化职业人格比喻、已有具体数据被概括覆盖、起手套话、五种翻译腔及段首缺回指评论。[S1]
- 作者明确反对为了制造人味而随机拆段、加口头禅、删除所有问句或比喻。[S1]
- 三个 Python 脚本用于目录级语料统计，不是自动改稿器，也没有提供可信的单篇 AI 味概率或发布通过标准。[S4–S6]
- 采用 MIT 许可证。若复制或修改其规则和脚本，应保留版权与许可文本，并记录来源及固定版本。[S7]
- README 提供 Skill 安装命令及直接作为提示词的用法；使用这些规则并不要求接入 Moxt 平台。[S2]

## 3. 证据与风险

### 3.1 研究只能作启发，不能作已独立验证的定律

作者报告 629 篇、约 283 万汉字，生成侧为五个模型各 60 篇，人类侧 329 篇。[S2–S3]

但原始语料未公开，第三方无法复算这些数字；话题未严格配对，部分翻译腔缺人类侧对照，正则也不能准确理解语义。[S2–S3] 本轮没有独立验证其倍率，更没有在用户实际稿件上证明有效。

上游还存在证据表述不一致：README 局限称部分翻译腔未计算人类侧比值，RESEARCH 却笼统给出五种句式的人类侧倍率。不能把后者直接作为确定结论。[S2–S3]

### 3.2 规则示例可能损伤信息守恒

- 第 1 条把“不是技术，而是认知”改成“是认知”，可能丢失作者对技术因素的明确否定；只有该对照纯属修辞、没有实质判断时才能删。
- 第 2 条把“采集、存储、展示”改成“从采集到展示”，隐藏了明确列出的存储环节。
- 第 7 条将“永不疲倦的审查员”改成“不会疲倦”，可能把宣传比喻改成未经证实的能力断言。
- 第 10 条将“留存率涨到 72%，这意味着产品找到了 PMF”连成一句，仍保留原稿可能未经证实的推断。语言清理不能代替事实及判断核验。

因此，采用原则和经过筛选的规则，不盲从示例；有歧义就保留原句或交编辑判断。[S1]

### 3.3 脚本不宜直接当生产门禁

静态阅读发现以下不一致，无需运行生产稿件即可确认：[S4–S6]

- `check-structure.py` 按单行处理“段落”，没有按空行分段，也未维护代码围栏状态；不能与文档的段落切分合同等同。
- 段首零主语检测只检查起始词，不能判断完整句子是否已经存在回指成分。例如“听起来，这个方案……”仍可能被计入。
- 相邻句同构主要比较逗号数量、冒号、括号和长度档，不等于理解句法或确认模板化表达。
- `compare-human-ai.py` 的“序数词当小标题”正则未要求 Markdown 标题标记，会计入普通正文的“首先，”；规则编号也与现版 Skill 不完全一致。
- 该脚本倍率方向为“人类 / AI”，而研究文档使用“AI / 人类”，对接报告时不能混用。
- 统计脚本未完整实现白名单中的语义豁免，不能把所有正则命中都当作必须改写项。

## 4. 当前写作系统的真实接点

本地代码确认，当前模型审改已经存在：[L1–L4]

```text
事实与读者价值准备 → 主写作 → 读者侧编辑/初次质检
→ human-writing 终稿审改 → 校验/复检 → 文本卫生
→ 发布附属文案和图片 → HotNow 交付
```

- 长文：`write_workflow_v2.py` 在 Step5 内调用 `review_long_content`。
- 短文：`short_content_writer.py` 的 `apply_human_writing_review` 在初检通过后调用审改，复检失败回退合格原稿。
- 公共适配器：`~/.hermes/scripts/hotnow/human_writing_review.py`，负责 Skill 解析、只读提示词、有限尝试、校验、追踪和回退。
- Skill 优先路径为 `~/.codex/skills/human-writing`，当前链接到共享 Skills 仓库的 `skill-packages/vendor/human-writing`；不是本会话 Pi Skill 目录。只改 Pi 目录不等于改变 Hermes 生产写作。
- 当前适配器要求 `VERSION`，长文要求 `scripts/check_prose.py`；目标仓库没有提供这套同名兼容合同，不能直接替换目录。
- 现有共同校验比较图片标记及阿拉伯数字集合，不是完整语义保真验证。例如“可能”被删除、人物替换或因果变强，不会仅因数字校验而被发现。
- `watermark_text_hygiene.py` 是文本卫生工具，不负责提高论证质量或改写文风。

HotNow 只保存、展示及代理控制，不应新增本地去味模型调用、队列或自动化状态机。[L1]

## 5. 与 human-writing 的重叠和冲突

| 维度 | 当前 human-writing | 上游去味 Skill | 建议 |
| --- | --- | --- | --- |
| 任务范围 | 通用创作与审改，强调材料和读者推进 | 只做成稿局部清理，不解决结构质量 | 分清职责，不拿局部去味替代写作 |
| 事实 | 不编亲历、案例、引语 | 信息守恒，限定词也不能删除 | 共同保留并加强核验 |
| 标点 | 广泛禁止破折号，冒号豁免较少 | 按用途判断，允许风格和体裁豁免 | 首版保留现役合同，不静默放宽 |
| 排比 | 三项以上同构排比受限 | 保留句内排比，重点处理句间同构 | 先测误伤，再单独决策是否改旧规则 |
| 比喻 | 非虚构抽象借喻限制较多 | 主要针对理想化职业人格 | 不把两套禁令简单累加 |
| 引语 | 命中禁令可转述或省略 | 引用原文不改 | 逐字引语锁定，必要时由主编辑作显式转述 |
| 段落和框架 | 可按读者需求编辑表达与节奏 | 局部清理必须保持框架 | 清理阶段固定框架，结构问题留给前序编辑 |
| 输出 | Hermes 要求结构化 JSON | 上游默认只输出改写全文 | 保留 Hermes 的 JSON 和字段合同 |

当前 human-writing 是共享 Skill，直接修改它可能影响其他写作任务。首选将筛选后的补充规则限定在 Hermes 的终稿审改使用场景，避免无关任务同步受影响。[L2–L4]

## 6. 推荐的最小接入方案

### 第一阶段：先做不入库的样稿对照

请用户提供或明确授权读取 10–20 篇稿件的离线副本，覆盖长文、科技新闻、短内容、教程以及含引用、表格、链接的文章。不得直接扫描 live 数据库。

对同一份终稿候选对比：

- A：现有 human-writing 审改。
- B：现有审改加经过冲突裁决的局部去味规则。

盲评自然度、清晰度、信息量、判断分寸，同时记录事实漂移、误伤、耗时和实际模型用量。不预先声称 B 更好。

### 第二阶段：同一审改调用内吸收规则

保留 `human_writing_review.py` 的调用阶段、允许模型、最多两次尝试、JSON 输出、队列与失败回退。

将筛选后的规则作为显式本地参考文件或提示词补充，由适配器明确加载；安装到 Skill 目录本身不算接通。初版优先补强：

1. 只修改有明确原因的表达，未命中句子保持原样，不顺手全篇润色。
2. 对相邻句同构只做必要句内调整，操作步骤、法规和有意排比豁免。
3. 补清段首评论对象，但不能因加“这”形成指代歧义。
4. 用已有具体信息替代空泛概括，不新增数据或删除明确环节。
5. 处理确有阅读障碍的过长前置定语、重复话题壳和同义复述，不删除实质时间、转折或因果关系。
6. 保护正常问句、逐字引用、链接、专业术语、代码及有指代作用的编号。

不整体叠加两份 SKILL.md。规则优先级明确为：事实与引语保真、平台锁定字段、具体文体及用户意图、已裁决的审改规则。现役硬规则的放宽需另行确认并同步检查器，不靠提示词暗中覆盖。

B 方案不默认增加模型调用次数，但额外提示词仍会增加输入用量，并可能影响耗时与重试，须实测。

### 第三阶段：质量保障先于自动发布

- 本地校验结构、图片、链接、代码和数字，语义质检复用现有门禁，特别检查人名、日期、限定词、时间关系及判断强度。正则校验不能证明完整事实保真。
- 检查失败沿用原有限预算；仍失败回退前一份合格稿。记录真实“回退”，不能显示为去味通过。
- 发布用标题、导语、评论和拓展也可能有 AI 腔。先在它们现有生成请求内加入简短适用规则，保留正文事实来源，不新增全篇清理轮次。
- 规则版本变化必须纳入成功调用与恢复检查点的输入/策略指纹；不要让旧检查点冒充新策略已执行，也不批量重写已受理任务和历史文章。
- 保留上游许可证、固定版本及本地差异，后续更新经过审查，不在运行时联网拉取规则。

第一版不新增 HotNow 按钮、数据库字段、独立评分或全局共享 Skill 重写。

发布前真实模型对照仍待完成。技术测试通过不等于真实写作质量验收通过；读者盲评及人工抽查不可省略。

> 对下面的成稿做局部语言清理。仅采用已明确列出的去 AI 味规则，不全篇润色，不改变框架。保留所有事实、观点、限定词、否定关系、时间关系、引用和链接。没有命中或无法确认命中的句子逐字保留。不能补经历、数字、因果、场景和案例。规则示例与信息守恒冲突时，以信息守恒为准。教程步骤、法规编号、专业术语、代码、逐字引语及正常问句不改。另附仅供编辑查看的改动对照，注明规则和理由，不把检查过程写进文章正文。
