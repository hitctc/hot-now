# 性能优化基线

## 目标与范围

本轮优先覆盖 AI 新讯、AI 热点、公众号素材、短内容素材、成品文章、短内容成品、文章详情、写作队列状态及数据来源工作台。旧报告、历史页和控制台不进入第一轮。

验收目标：

- 常用列表首屏在 `1` 秒内显示数据。
- 翻页、筛选和刷新在 `800` 毫秒内完成。
- 文章详情在 `1` 秒内打开。
- 普通操作在 `300` 毫秒内给出明确反馈。
- 关键接口 P95 相对基线至少下降 `50%`。
- 不减少数据、不破坏跨项目接口兼容、不新增测试失败。

## 2026-07-31 生产基线

测试方式：从生产服务器本机连续请求五次，记录 Fastify 接口总耗时和响应字节数。数据库共 `7896` 条创作素材、`1216` 篇成品文章，SQLite 文件约 `282MB`。

| 接口 | 每页 | 耗时范围 | 响应大小 |
| --- | ---: | ---: | ---: |
| 公众号素材 | 50 | 916.8～1126.6ms | 807685 bytes |
| 成品文章 | 50 | 122.2～162.7ms | 2521679 bytes |
| Hermes 写作队列状态 | - | 50.8～154.7ms | 519 bytes |

短内容的正确方向值为 `short_content`；早期探测误用了 `short`，对应空结果不纳入基线。

## 已确认的瓶颈证据

1. 素材列表和成品文章列表都读取完整详情字段。素材包含 `full_content`、`raw_payload_json`，成品文章包含正文、人工稿、证据包、提示词、HTML 和阶段轨迹，导致列表响应达到数百 KB 至数 MB。
2. 素材默认查询只有独立的 `direction` 和 `created_at` 索引，SQLite 需要扫描同方向数据并创建临时 B-tree 排序。
3. 成品文章排序包含冗余的 `(pinned_at IS NOT NULL)` 表达式，现有 `direction, pinned_at, created_at` 索引无法直接完成排序。
4. 草稿推送成功次数的相关子查询只有单列索引，没有 `(article_id, status)` 复合索引。

## 本地生产快照实验

实验只在 verified copy 上进行，没有修改生产库。按用户确认后的每页 `30` 条测试：

| 查询 | 优化前中位数 | 实验索引后中位数 |
| --- | ---: | ---: |
| 公众号素材 | 157.4ms | 2.8ms |
| 短内容素材 | 约 10ms（50 条） | 0.5ms |
| 成品文章 | 19.0ms | 8.5ms |
| 短内容成品 | 约 10ms（50 条） | 1.0ms |

实验索引消除了两个核心列表执行计划中的临时 B-tree 排序。下一批仍需改为轻量列表模型，继续降低 JSON 解析、序列化、网络传输和 Vue 响应式处理成本。

## 监测约定

- 服务端默认只记录不低于 `500ms` 的慢请求，可用 `HOT_NOW_SLOW_REQUEST_MS` 调整。
- 每个响应包含 `Server-Timing`，便于在浏览器开发者工具区分服务端耗时和网络／前端耗时。
- 前端开发模式只在请求超过 `500ms` 时输出脱敏路径、状态码、总耗时和服务端计时。
- 正常快速请求保持静默，日志不包含查询参数、正文、Cookie 或密钥。
