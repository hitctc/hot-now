# 短内容代码制图开发方案

## 1. 文档状态

- 状态：已实现并部署；生产中文字体、三比例渲染、标签生成和公众号草稿推送链路已验证，历史 `stale` 图片按篇重做
- 适用范围：HotNow 短内容自动／人工制图、长文手动复用三比例制图、公众号草稿推送；长文不自动插入正文
- 目标：为每篇短内容成品制作三张可复用的品牌图片，并接入现有正文、封面和草稿推送流程

## 2. 背景与问题

本方案实施前，短内容成品缺少封面图和正文图，因此：

- 成品详情中的封面图区域长期为空；
- 现有“缺少封面”校验会阻止短内容推送到公众号草稿箱；
- 需要一种不依赖 AI 生图、成本低、风格统一、生成速度快的图片制作方式。

本方案使用代码排版和导出图片，不调用图像生成模型。

## 3. 已确认需求

### 3.1 制作范围

- Hermes 当前自动短写批次定向成品回推成功后，沿原交付流程触发单篇三比例制图；历史批量补推不隐式触发。
- HotNow 现有可推送状态为 `ready_for_publish`；人工或自动流程的具体状态转换继续复用现有状态机。
- 人工短写、空白人工创建和编辑保存不隐式触发制图；用户可在单篇列表或详情显式制作。
- 历史成品不自动批量处理，只支持单篇制作。
- 单篇制作入口放在：
  - 短内容成品列表每行操作区；
  - 短内容成品详情弹窗图片区域。
- 不提供批量制作按钮。
- 制作图片不限次数：页面按钮始终可用，每次都整组重做三张图（包括已成功的图片）。
- 代码图片是本地确定性渲染，不消耗外部模型额度，因此不再用“已有完整图片”限制按钮。
- 图片内容变化后会标记为可能过期，但该标记只影响状态文案，不影响能否重做。

### 3.2 三张图片规格

| 比例 | 尺寸 | 内容 | 用途 |
| --- | --- | --- | --- |
| `2.5:1` | `1500 × 600`（逻辑画布 `750 × 300`） | 标题、核心判断、导语/摘要、真实素材标签、HotNow 标识 | 横向分享；长文无已有选择时优先封面 |
| `1:1` | `1500 × 1500`（逻辑画布 `750 × 750`） | 标题、真实素材标签、HotNow 标识 | 新短内容默认封面与方形分享 |
| `3:4` | `1500 × 2000`（逻辑画布 `750 × 1000`） | 标题、核心判断、导语/摘要、真实素材标签、HotNow 标识 | 竖图分享和封面候选 |

导出格式为 PNG。使用无损压缩、压缩级别、调色板和元数据清理控制体积，单张图片目标体积约为 `300～500KB`，以文字清晰度优先。

### 3.3 文案来源

- 标题：当前成品最终选中的标题；没有有效选中标题时取第一条有效标题。
- 主体文案：按 `thesis`、`reversalAngle`、选中的 `intros`、选中的 `summary100`、素材 `summary`、标题依次回退；不允许输出空内容占位文案。
- 核心标签：优先使用成品文章的 `codeImageKeywords`，其次使用素材真实提供的 `tags`；没有真实标签时不显示标签，不把标题拆分后冒充标签。
- 标签自动生成与手动生成：
  - 自动：Hermes 短内容写作输出 2～3 个标签；模型漏给时 Hermes 单独补一次生成。
  - 手动：详情弹窗点“生成标签 / 重新生成标签”，HotNow 代理 Hermes `/api/regen-code-image-keywords` 生成并 **覆盖** 旧标签。
  - 覆盖语义：`codeImageKeywords` 是制图直接读取的最终标签（最多 3 个），不做多候选，否则制图无法决定用哪组。已有标签时先弹确认。
  - 长短内容均可显式手动生成标签，调用 Hermes 唯一模型队列；新长文在既有发布文案请求中同步生成，漏标签不追加请求、不阻断交付。
  - 标签变化会把已有代码图片标记为 `stale`，需要重新制作图片。
- 标签在成品详情弹窗的「备选标题」下方单独展示；没有标签时也要保留该区域并说明原因，方便区分“写作未产出”和“前端未显示”。
- 排版硬约束：`fitText` 返回换行时选中的字号，绘制必须使用该字号；否则按初始字号绘制会让行宽超出换行宽度，横图和方图都会在画布右侧被裁掉。标签胶囊宽度由保守文本宽度推导，放不下时整颗胶囊跳过。
- 标签提取属于文章生成阶段的数据契约，由 Hermes 生成并随成品推送，HotNow 持久化后只负责展示和制图。
- 不调用 AI 重新生成图片文案。

### 3.4 长文本处理

- `2.5:1` 标题最多显示 2 行。
- `1:1` 标题最多显示 4 行，基础字号为逻辑画布字号 `120`，最小为 `60`；在固定标题区域内按标题长度及可用高度缩小，达到最小字号仍超出时使用省略号。
- `3:4` 标题最多显示 4 行。
- 优先自适应缩小字号。
- 仍无法容纳时使用省略号，完整标题仍保留在正文和文章数据中。
- 横图核心判断/导语基础字号为逻辑画布字号 `38`，最多显示 2 行；短标题时从 `y=110` 起排，双行标题时跟随标题向下，但仍按剩余高度缩小以避开 `y=228` 的标签行。超出后自适应缩小并在必要时省略。
- 关键词标签每个尽量控制在 8 个汉字以内，过长时由代码缩短。

### 3.5 视觉模板

三种比例共用一套独立的 HotNow 品牌模板，不跟随公众号正文主题切换：

- 背景：浅紫白，基于 `#f8f5ff`；
- 主文字：深紫黑，基于 `#1a1525`；
- 强调色：淡紫，基于 `#caa9fa`；
- 辅助装饰：少量暖色线条或几何元素；
- 背景只由代码绘制，不使用文章原图或外部网络图片；
- 服务端随应用部署 `NotoSansSC-Regular.otf`，启动渲染器时注册到当前进程的 fontconfig；客户端/本地预览再回退到 `PingFang SC → Noto Sans SC → sans-serif`，避免生产环境缺少 CJK 字体导致乱码；
- 复用现有 `hotnow-logo-mark.png`，搭配 `HotNow` 文字；
- Logo 固定放在右下角，三种比例保持一致的视觉权重；
- 全部左对齐并保留安全边距。

初版排版：

- `2.5:1`：标题左上/左中，右上装饰线固定在标题上方避免双行长标题遮挡，导语向标题靠近并与下方固定标签留出间距，Logo 右下；
- `1:1`：标题位于固定上方区域，最多 4 行，基础字号为逻辑画布字号 `120`，最小字号 `60`；只展示标题和关键词标签，不绘制核心判断或导语/摘要。标签基础字号为 `62`，最多 3 枚，可换成两行；标签底部与右下 Logo 留出间距；
- `3:4`：标题、导语和标签的基础逻辑字号分别为 `66`、`55`、`48`；导语随标题和标签之间的可用高度缩小，居中分配上下留白；标签最多两行并避开右下 Logo。

方图保留浅紫白背景、品牌标识和装饰图形；以上字号应用于 `750 × 750` 逻辑画布，导出 PNG 为 `1500 × 1500`。

### 3.6 正文写入

短内容代码图片成功生成后，将成功图片链接写入人工发布正文 `humanMarkdown`，不改 AI 草稿 `contentMarkdown`；人工正文为空时也不复制原稿。部分成功只插入成功图片，显式重做会替换正文中已有的旧代码图片链接并补入本次成功图片，不重复追加。普通正文保存不从封面候选自动补回用户已删除的图片；长文制图不自动写入正文。

历史稿不批量回填或重做，不自动删除已插入图片、不调整已选封面；旧图需重新制作后才按当前规则写入人工正文。

### 3.7 封面图与公众号推送

代码制图片需要接入现有封面逻辑，而不是只作为推送时的临时回退：

- 三张成功图片都写入独立的代码制图片元数据；
- 三张成功图片 URL 同步写入现有 `coverImage`，作为封面候选；
- 新短内容没有已有封面选择时，默认选择 `1:1` 方图；长文保留默认 `2.5:1` 横图；
- 有传统封面时，不覆盖当前传统封面，代码制图片追加为候选；
- 用户可手动选任意候选，后续重做保留所选图片或比例；短内容按钮常驻图片下方，点击高度至少44px，紫色高对比底色；当前封面标识加大，不依赖悬停，长文样式不变；
- 默认比例缺失时回退到 `3:4`，再回退到首张可用候选；
- 至少一张代码制图片成功时，允许推送到公众号草稿箱；
- 三张都失败且没有传统封面时，继续提示缺少封面；
- 现有公众号推送逻辑不增加代码制图片专用分支，统一使用最终可用封面；
- 短内容正文包含成功生成的代码图片链接，草稿推送使用人工发布正文；封面仍沿用最终选中图片，正文图片按现有推送流程独立上传，不复用封面素材 URL，也不强制覆盖用户选择。

如果已有传统封面，代码制图片仍会作为候选追加，并保持当前传统封面为已选封面，避免自动制作过程改变既有选择。

### 3.8 状态与失败处理

代码制图片独立于文章状态，建议记录以下状态：

- `pending`：尚未制作；
- `running`：制作中；
- `succeeded`：制作成功；
- `partial`：部分比例成功；
- `failed`：全部失败；
- `stale`：依赖内容或模板已变化，现有图片可能过期。

规则：

- 图片制作失败不改变文章现有状态（包括 `ready_for_publish`）；
- 单张失败不影响其他图片；
- 成功图片写入独立元数据和 `coverImage` 候选；短内容将成功图片插入人工发布正文，AI 草稿和长文正文不变；
- 失败图片不写入空链接；
- Hermes 负责自动触发和重试，HotNow 不新增自动化队列；
- 同一篇文章同时只允许一个制作任务；重复触发返回当前状态，不重复写文件或追加候选；
- 文章标题、`thesis`、关键词变化时标记过期；
- 普通正文段落变化不标记过期；
- 模板、Logo 或尺寸规则变化时标记相关图片过期；横图、方图和竖图分别使用独立版式指纹，单篇补做时只更新改版的比例，不影响其他比例。横图与竖图导语加深为 `#352842` 并提高字重后仅更新这两种比例；方图保持原图。

### 3.9 文件存储

复用 HotNow 现有 `creativeImageDir` 和图片公开读取接口，不新增独立图片目录：

```text
生产目录：/srv/hot-now/shared/data/creative-images/
文件目录：/srv/hot-now/shared/data/creative-images/YYYY-MM-DD/
访问地址：https://now.achuan.cc/api/creative/images/YYYY-MM-DD/<uuid>.png
```

约束：

- 图片保存在 `shared/data`，不放入代码树、`dist/`、报告目录或 Git；
- 继续按日期分目录；
- 使用 UUID 文件名，避免重做冲突；
- 旧图片文件不自动删除，避免已经被用作封面或转发后链接失效；
- 成品记录只指向当前有效图片版本，历史文件由后续独立清理方案处理。

### 3.10 数据结构

新增独立的代码制图片元数据，不复用现有 AI 图片字段。建议在成品记录增加 `code_image_cards` JSON 字段，客户端映射为 `codeImageCards`。

每个比例至少保存：

```json
{
  "variant": "2.5:1",
  "url": "/api/creative/images/2026-09-16/<uuid>.png",
  "width": 1500,
  "height": 600,
  "status": "succeeded",
  "generatedAt": "2026-09-16T12:00:00.000Z",
  "sourceFingerprint": "...",
  "fileSize": 321456,
  "error": null
}
```

成品文章另存 `codeImageKeywords` JSON 字段，保存文章生成阶段产出的 2～3 个真实主题标签。

`sourceFingerprint` 至少由以下内容组成：

- 当前选中的标题；
- `thesis` 或最终回退的主体文案；
- 规范化后的 `codeImageKeywords` / 素材关键词；
- 模板版本；
- Logo 版本；
- 输出尺寸版本。

### 3.11 页面能力

短内容成品列表和详情弹窗需要展示：

- 三种比例的预览图；
- 图片制作状态；
- 比例和尺寸；
- 失败原因或过期提示；
- “制作图片”或“补做图片”；
- 内容变化后的“重新制作图片”；
- “下载 PNG”；
- “复制图片地址”。

不新增“批量制作图片”入口。

### 3.12 自动化职责

- Hermes：在原自动短写定向交付成功后触发单篇 HotNow 代码制图接口，沿原流程重试；不因平台人工创建/保存短稿增加触发。
- HotNow：读取最终成品数据，完成 SVG 排版、Sharp 导出、文件保存、图片元数据/封面候选回写和状态返回；短内容成功图片同步写入人工发布正文，AI 草稿及长文正文不变。
- HotNow 不复制 Hermes 的自动化队列、调度、重试或业务判断。
- 图片制作不阻塞文章进入 `ready`，也不要求等待 AI 生图。

## 4. 建议接口

具体路径沿用现有 Creative 路由和鉴权模式，最终实现时以现有路由装配为准。

### 4.1 Hermes 自动触发

由 Hermes 使用 Creative API token 调用单篇制作接口：

```text
POST /api/creative/finished-articles/:id/code-images
```

请求体可选：`{"mode":"missing"}`（补做缺失/失败图片，默认值）或 `{"mode":"all"}`（全部重做）。

接口要求：

- 接受长文和短内容成品；长文只供手动复用，不改变模型生图开关；
- 文章不存在或已删除时返回明确错误；
- 同一文章已有 `running` 任务时返回当前任务状态；
- 支持指定只补缺失或失败的比例；
- 支持明确的全部重做模式；
- 返回三种比例的状态和 URL。

### 4.2 页面单篇操作

页面通过 session 鉴权调用：

```text
POST /actions/creative/finished-articles/:id/code-images
```

页面操作不得创建 HotNow 自动队列，只触发当前文章的单次制作。

### 4.3 读取与下载

- 成品详情接口返回 `codeImageCards`；
- 图片预览复用现有图片读取路由；
- 下载使用现有公开图片 URL，不新增文件中转接口；
- 复制地址复制完整的公开 URL。

## 5. 实现边界

本轮包含：

- SVG + Sharp 的三比例图片渲染器；
- 图片压缩和现有图片存储接入；
- 代码制图片元数据和数据库迁移；
- 短内容制图将成功图片写入人工发布正文，长文制图不写正文；旧正文不批量清理；
- `coverImage` 候选和当前封面校验接入；
- 公众号草稿推送的最终可用封面判断；
- Hermes 原自动短写定向交付成功后触发；
- 列表和详情弹窗的单篇制作、状态、预览、下载和复制；

已落地文件：

- `src/core/creative/codeImageCardsRenderer.ts`：SVG + Sharp 三比例渲染器，增大文案字号并收紧布局；
- `src/core/runtime/configureFontconfig.ts`：为 librsvg 注册应用内中文字体目录；
- `src/server/public/fonts/NotoSansSC-Regular.otf`、`src/server/public/fonts/OFL.txt`：随应用部署的中文字体及其 SIL Open Font License；
- `src/core/creative/codeImageCardsService.ts`：单篇幂等制作、封面候选回写、版本保护；
- `src/core/db/migrations/051_finished_articles_code_image_cards.ts`：`code_image_cards` 字段迁移；
- `src/core/db/migrations/052_refresh_code_image_cards_template.ts`、`053_refresh_code_image_cards_fontconfig.ts`：将旧版和 fontconfig 修复前的图片标记为 `stale`，支持逐篇重做；
- `src/core/db/migrations/054_finished_articles_code_image_keywords.ts`：保存文章生成阶段产出的代码图片主题标签；
- `src/server/routes/creativeFinishedArticleImageRoutes.ts`：Hermes token 与页面 session 接口；
- `src/client/components/creative/article-detail/CodeImageCardsSection.vue`：列表/详情操作入口；
- Hermes 仓库的 `scripts/hotnow/short_content_pusher.py`：当前自动写作批次成品推送成功后触发制作，历史批量推送不触发代码制图；
- 相关单元测试、接口测试和客户端测试；
- README、AGENTS 和必要的协作说明同步。

发布时已完成代码制图专项路由与渲染测试、字体嵌入样图检查、HotNow 全量测试和构建。Hermes 自动化测试仍有一项既有的 `check_body` 调用次数断言失败，与本功能无关。

本轮不包含：

- AI 生图；
- 图片内容再次调用 LLM 生成；
- 批量历史补做；
- 自动设为公众号封面以外的额外发布动作；
- 自动决定用户最终保留哪些正文图片；
- 自动删除旧图片文件；
- 新增 HotNow 自动化队列、调度器或独立重试系统；
- 重新设计现有公众号正文主题。

## 6. 测试与验收标准

### 6.1 渲染器

- 三种输出尺寸和比例准确；
- 标题、核心判断和关键词按规则换行、缩小和省略；
- 中文字体回退正常；
- Logo 能正确嵌入；
- PNG 可正常打开，文字清晰；
- 文件体积符合目标范围或在极端文本下有明确降级结果。

### 6.2 数据与正文

- 成功图片写入 `codeImageCards`、`coverImage`；短内容生成后把成功图片插入 `humanMarkdown`，不改 AI 草稿，长文仍不自动插图；新短内容默认方图，后续正文保存不从封面候选补图；
- AI 草稿 `contentMarkdown` 不被修改；

## 8. 风险与取舍

- PNG 对文字清晰度友好，但复杂渐变可能导致体积增大；优先保持文字清晰，再通过压缩和减少装饰控制体积。公众号草稿的代码图封面在 PNG 不超过 2 MB 时保留原图，不转 JPEG；正文中的同图独立走正文 PNG 上传，不复用永久素材 URL。微信 CDN 和终端缩放仍可能二次处理，不能保证微信端像素与本地原件完全一致。
- 服务器字体环境可能与本地不同；实现时必须验证生产字体回退和中文显示。
- 短内容代码图片成功生成后写入人工发布正文，并随其进入草稿；AI 草稿和长文正文不变。旧稿不批量补图，重做替换已有链接并补入本次重新生成的图片。
- 旧图片保留会持续占用存储空间，但可以避免历史封面和转发链接失效；清理功能不在本轮处理。
- `coverImage` 继续承载封面候选，代码制图片通过独立元数据标识来源，避免与 AI 图片状态混淆。
