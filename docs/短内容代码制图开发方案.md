# 短内容代码制图开发方案

## 1. 文档状态

- 状态：已实现，待生产部署与线上 smoke test
- 适用范围：HotNow 短内容成品、Hermes 自动化触发、公众号草稿推送
- 目标：为每篇短内容成品制作三张可复用的品牌图片，并接入现有正文、封面和草稿推送流程

## 2. 背景与问题

当前短内容成品没有封面图和正文图，因此：

- 成品详情中的封面图区域长期为空；
- 现有“缺少封面”校验会阻止短内容推送到公众号草稿箱；
- 需要一种不依赖 AI 生图、成本低、风格统一、生成速度快的图片制作方式。

本方案使用代码排版和导出图片，不调用图像生成模型。

## 3. 已确认需求

### 3.1 制作范围

- 所有未来完成写作并最终落库的、未删除的 `short_content` 成品自动制作三张图片。
- HotNow 现有可推送状态为 `ready_for_publish`；人工或自动流程的具体状态转换继续复用现有状态机。
- 覆盖自动写作、人工创建、人工改写后重新完成的短内容。
- 历史成品不自动批量处理，只支持单篇制作。
- 单篇制作入口放在：
  - 短内容成品列表每行操作区；
  - 短内容成品详情弹窗图片区域。
- 不提供批量制作按钮。
- 已有完整图片时不重复制作；缺失或失败的图片可以单独补做。
- 图片内容变化后标记为可能过期，用户明确执行“重新制作图片”时重做当前文章的三张图。

### 3.2 三张图片规格

| 比例 | 尺寸 | 内容 | 用途 |
| --- | --- | --- | --- |
| `2.5:1` | `750 × 300` | 标题、核心判断、HotNow 标识 | 公众号主要展示和优先封面 |
| `1:1` | `750 × 750` | 标题、2～3 个核心关键词、HotNow 标识 | 方形分享和封面候选 |
| `3:4` | `750 × 1000` | 标题、核心判断、2～3 个核心关键词、HotNow 标识 | 竖图分享和封面候选 |

导出格式为 PNG。使用无损压缩、压缩级别、调色板和元数据清理控制体积，单张图片目标体积约为 `300～500KB`，以文字清晰度优先。

### 3.3 文案来源

- 标题：当前成品最终选中的标题；没有有效选中标题时取第一条有效标题。
- 核心判断：成品 `thesis`。
- 核心关键词：素材已有 `tags`。
- 关键词缺失或不足时，由代码从标题和核心判断中做确定性兜底提取。
- 不调用 AI 重新生成图片文案。

### 3.4 长文本处理

- `2.5:1` 标题最多显示 2 行。
- `1:1` 标题最多显示 3 行。
- `3:4` 标题最多显示 4 行。
- 优先自适应缩小字号。
- 仍无法容纳时使用省略号，完整标题仍保留在正文和文章数据中。
- 横图核心判断最多显示 2 行，超出后自适应缩小并在必要时省略。
- 关键词标签每个尽量控制在 8 个汉字以内，过长时由代码缩短。

### 3.5 视觉模板

三种比例共用一套独立的 HotNow 品牌模板，不跟随公众号正文主题切换：

- 背景：浅紫白，基于 `#f8f5ff`；
- 主文字：深紫黑，基于 `#1a1525`；
- 强调色：淡紫，基于 `#caa9fa`；
- 辅助装饰：少量暖色线条或几何元素；
- 背景只由代码绘制，不使用文章原图或外部网络图片；
- 字体使用 `PingFang SC → Noto Sans SC → sans-serif`；
- 复用现有 `hotnow-logo-mark.png`，搭配 `HotNow` 文字；
- Logo 固定放在右下角，三种比例保持一致的视觉权重；
- 全部左对齐并保留安全边距。

初版排版：

- `2.5:1`：标题左上/左中，核心判断左下，Logo 右下；
- `1:1`：标题上方，关键词标签下方，Logo 右下；
- `3:4`：标题上方，核心判断居中偏上，关键词标签下方，Logo 右下。

### 3.6 正文写入

三张图都写入 `humanMarkdown`，不修改 `contentMarkdown`，插入到正文开头。用户可以在发布前自行删除或保留任意图片。

为兼容现有封面图和正文图合并逻辑，Markdown 描述使用以下形式：

```md
![封面图｜HotNow 2.5:1 横图](横图地址)

![配图｜HotNow 1:1 方图](方图地址)

![配图｜HotNow 3:4 竖图](竖图地址)
```

页面渲染时只显示图片，比例说明保存在图片描述中。

重做时：

- 找到正文中已有的代码制图片并替换 URL；
- 保留图片原来在正文中的位置；
- 用户已手动删除的图片不自动恢复；
- “补做缺失图片”时，才将缺失图片插回正文开头；
- 不重复追加多组三张图片。

### 3.7 封面图与公众号推送

代码制图片需要接入现有封面逻辑，而不是只作为推送时的临时回退：

- 三张成功图片都写入独立的代码制图片元数据；
- 三张成功图片 URL 同步写入现有 `coverImage`，作为封面候选；
- 没有传统封面时，默认选择 `2.5:1` 横图；
- 有传统封面时，不覆盖当前传统封面，代码制图片追加为候选；
- 用户可以在详情弹窗中把 `1:1` 或 `3:4` 手动设为发布封面；
- 如果 `2.5:1` 失败，封面优先回退到 `3:4`，再回退到 `1:1`；
- 至少一张代码制图片成功时，允许推送到公众号草稿箱；
- 三张都失败且没有传统封面时，继续提示缺少封面；
- 现有公众号推送逻辑不增加代码制图片专用分支，统一使用最终可用封面；
- 用户发布前是否保留三张正文图片，由用户自己编辑决定。

如果已有传统封面，代码制图片仍会作为候选追加，并保持当前传统封面为已选封面，避免自动制作过程改变既有选择。

### 3.8 状态与失败处理

代码制图片独立于文章状态，建议记录以下状态：

- `pending`：尚未制作；
- `running`：制作中；
- `succeeded`：制作成功；
- `partial`：部分比例成功；
- `failed`：全部失败；
- `stale`：依赖内容或模板已变化，现有图片可能过期。

规则：

- 图片制作失败不改变文章现有状态（包括 `ready_for_publish`）；
- 单张失败不影响其他图片；
- 成功图片立即写入正文和 `coverImage`；
- 失败图片不写入空链接；
- Hermes 负责自动触发和重试，HotNow 不新增自动化队列；
- 同一篇文章同时只允许一个制作任务；重复触发返回当前状态，不重复写文件、写正文或追加候选；
- 文章标题、`thesis`、关键词变化时标记过期；
- 普通正文段落变化不标记过期；
- 模板、Logo 或尺寸规则变化时标记相关图片过期。

### 3.9 文件存储

复用 HotNow 现有 `creativeImageDir` 和图片公开读取接口，不新增独立图片目录：

```text
生产目录：/srv/hot-now/shared/data/creative-images/
文件目录：/srv/hot-now/shared/data/creative-images/YYYY-MM-DD/
访问地址：https://now.achuan.cc/api/creative/images/YYYY-MM-DD/<uuid>.png
```

约束：

- 图片保存在 `shared/data`，不放入代码树、`dist/`、报告目录或 Git；
- 继续按日期分目录；
- 使用 UUID 文件名，避免重做冲突；
- 旧图片文件不自动删除，避免已经被用作封面或转发后链接失效；
- 成品记录只指向当前有效图片版本，历史文件由后续独立清理方案处理。

### 3.10 数据结构

新增独立的代码制图片元数据，不复用现有 AI 图片字段。建议在成品记录增加 `code_image_cards` JSON 字段，客户端映射为 `codeImageCards`。

每个比例至少保存：

```json
{
  "variant": "2.5:1",
  "url": "/api/creative/images/2026-09-16/<uuid>.png",
  "width": 750,
  "height": 300,
  "status": "succeeded",
  "generatedAt": "2026-09-16T12:00:00.000Z",
  "sourceFingerprint": "...",
  "fileSize": 321456,
  "error": null
}
```

`sourceFingerprint` 至少由以下内容组成：

- 当前选中的标题；
- `thesis`；
- 规范化后的关键词；
- 模板版本；
- Logo 版本；
- 输出尺寸版本。

### 3.11 页面能力

短内容成品列表和详情弹窗需要展示：

- 三种比例的预览图；
- 图片制作状态；
- 比例和尺寸；
- 失败原因或过期提示；
- “制作图片”或“补做图片”；
- 内容变化后的“重新制作图片”；
- “下载 PNG”；
- “复制图片地址”。

不新增“批量制作图片”入口。

### 3.12 自动化职责

- Hermes：在短内容进入 `ready` 后触发 HotNow 代码制图接口，并负责自动重试。
- HotNow：读取最终成品数据，完成 SVG 排版、Sharp 导出、文件保存、数据库回写、正文回写和状态返回。
- HotNow 不复制 Hermes 的自动化队列、调度、重试或业务判断。
- 图片制作不阻塞文章进入 `ready`，也不要求等待 AI 生图。

## 4. 建议接口

具体路径沿用现有 Creative 路由和鉴权模式，最终实现时以现有路由装配为准。

### 4.1 Hermes 自动触发

由 Hermes 使用 Creative API token 调用单篇制作接口：

```text
POST /api/creative/finished-articles/:id/code-images
```

请求体可选：`{"mode":"missing"}`（补做缺失/失败图片，默认值）或 `{"mode":"all"}`（全部重做）。

接口要求：

- 只接受短内容成品；
- 文章不存在、已删除或不是 `short_content` 时返回明确错误；
- 同一文章已有 `running` 任务时返回当前任务状态；
- 支持指定只补缺失或失败的比例；
- 支持明确的全部重做模式；
- 返回三种比例的状态和 URL。

### 4.2 页面单篇操作

页面通过 session 鉴权调用：

```text
POST /actions/creative/finished-articles/:id/code-images
```

页面操作不得创建 HotNow 自动队列，只触发当前文章的单次制作。

### 4.3 读取与下载

- 成品详情接口返回 `codeImageCards`；
- 图片预览复用现有图片读取路由；
- 下载使用现有公开图片 URL，不新增文件中转接口；
- 复制地址复制完整的公开 URL。

## 5. 实现边界

本轮包含：

- SVG + Sharp 的三比例图片渲染器；
- 图片压缩和现有图片存储接入；
- 代码制图片元数据和数据库迁移；
- `humanMarkdown` 正文回写；
- `coverImage` 候选和当前封面校验接入；
- 公众号草稿推送的最终可用封面判断；
- Hermes `ready` 后触发；
- 列表和详情弹窗的单篇制作、状态、预览、下载和复制；

已落地文件：

- `src/core/creative/codeImageCardsRenderer.ts`：SVG + Sharp 三比例渲染器；
- `src/core/creative/codeImageCardsService.ts`：单篇幂等制作、正文/封面回写、版本保护；
- `src/core/db/migrations/051_finished_articles_code_image_cards.ts`：`code_image_cards` 字段迁移；
- `src/server/routes/creativeFinishedArticleImageRoutes.ts`：Hermes token 与页面 session 接口；
- `src/client/components/creative/article-detail/CodeImageCardsSection.vue`：列表/详情操作入口；
- `.hermes/scripts/hotnow/short_content_pusher.py`：当前自动写作批次成品推送成功后触发制作，历史批量推送不触发代码制图；
- 相关单元测试、接口测试和客户端测试；
- README、AGENTS 和必要的协作说明同步。

已完成验证：`npm run test`（701 passed, 1 skipped）、`npm run build`、代码制图专项路由与渲染测试；Hermes 自动化测试仍有两项既有账号适配断言失败，与本功能无关。

本轮不包含：

- AI 生图；
- 图片内容再次调用 LLM 生成；
- 批量历史补做；
- 自动设为公众号封面以外的额外发布动作；
- 自动决定用户最终保留哪些正文图片；
- 自动删除旧图片文件；
- 新增 HotNow 自动化队列、调度器或独立重试系统；
- 重新设计现有公众号正文主题。

## 6. 测试与验收标准

### 6.1 渲染器

- 三种输出尺寸和比例准确；
- 标题、核心判断和关键词按规则换行、缩小和省略；
- 中文字体回退正常；
- Logo 能正确嵌入；
- PNG 可正常打开，文字清晰；
- 文件体积符合目标范围或在极端文本下有明确降级结果。

### 6.2 数据与正文

- 成功图片写入 `codeImageCards`、`coverImage` 和 `humanMarkdown`；
- AI 草稿 `contentMarkdown` 不被修改；
- 重复触发不追加重复图片；
- 重做替换原有生成图并保留正文位置；
- 用户手动删除的图片不会在普通保存时自动恢复；
- 部分成功不会写入失败图片链接；
- 旧图片文件不被删除。

### 6.3 推送

- 没有传统封面时，代码制图片可以解除“缺少封面”阻断；
- 有传统封面时，传统封面仍保持当前选中状态；
- 代码制图片可以成为封面候选；
- 至少一张代码图成功时可推送草稿；
- 三张都失败且没有传统封面时仍然阻止推送；
- 现有 AI 封面和正文图流程不回归。

### 6.4 自动化与页面

- Hermes 在短内容最终落库后能触发，HotNow 不改变现有文章状态机；
- 历史文章只能单篇制作；
- 列表和详情按钮行为一致；
- 制作中重复点击不会产生并发任务；
- 页面能查看状态、预览、下载和复制地址；
- 图片失败不改变文章 `ready` 状态。

## 7. 实施顺序

1. 新增并测试 SVG + Sharp 图片渲染器。
2. 增加成品代码制图片元数据和数据库迁移。
3. 接入图片文件保存和读取 URL。
4. 实现单篇制作服务、状态、并发保护和重做逻辑。
5. 实现 `humanMarkdown`、`coverImage` 和封面校验接入。
6. 实现公众号草稿推送的最终可用封面判断。
7. 增加列表和详情弹窗操作及预览能力。
8. 在 Hermes `ready` 流程接入自动触发和重试。
9. 补齐测试、构建、文档同步和生产 smoke test。

## 8. 风险与取舍

- PNG 对文字清晰度友好，但复杂渐变可能导致体积增大；优先保持文字清晰，再通过压缩和减少装饰控制体积。
- 服务器字体环境可能与本地不同；实现时必须验证生产字体回退和中文显示。
- 代码制图片写回 `humanMarkdown` 后，用户若未在发布前删除，三张图片会按普通正文图片进入公众号；这是当前明确接受的行为。
- 旧图片保留会持续占用存储空间，但可以避免历史封面和转发链接失效；清理功能不在本轮处理。
- `coverImage` 继续承载封面候选，代码制图片通过独立元数据标识来源，避免与 AI 图片状态混淆。
