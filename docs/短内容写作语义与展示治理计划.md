# 短内容写作语义与展示治理计划

日期：2026-10-03。HotNow参考版本：`932fee5`；Hermes现役源码目录：`/Users/tc-nihao/.hermes`，参考HEAD：`432c0a3`。

**状态：历史治理计划，已完成阶段实现；最终验证/发布记录见[双线总体计划](./长短内容双线流程与复用优化计划.md)。** 用户确认统一短写并授权自行确定规格、执行部署和提交推送。本文保留治理前基线及当时兼容/验收清单；后续短成品已移除素材趋势，旧分列候选不再是现役展示。当前行为见README、Hermes边界与对应PRD，不把下面的历史“当前问题”或未确定建议当成待实施合同。

## 1. 结论

用户指出的“短内容已经不再是反转文或贴图文”有源码依据。现役选题、正文写作及质检已经改为**事实复盘＋客观判断的热点简报**，不要求制造反转。

当前问题是多层语义演进不同步，而不是仅有两个中文标签写错：

1. 写作方向已经变化，HotNow成品表、素材写作选项、人工新建和Hermes队列标签仍讲旧故事。
2. `form=tuwen/duanwen` 仍控制真实生成规格，但不能证明文章的写作方向，也不能证明最终有图/无图。
3. 成品表将所有非`tuwen`值显示为“反转文”，连空值、未知值也被虚构分类。
4. 成品“爆文”列混用成品质检分和素材趋势维度，容易把内容质量、选题价值、传播预测理解成同一评分。
5. 旧管理端需求仍描述反转管线，容易让后续开发重新恢复已经被淘汰的业务目标。

**已确认目标：撤销错误业务分类和展示推断，新短写采用统一生成策略，同时保留历史数据、旧请求和在途任务的兼容边界。** 这是原B方向的确认，不代表代码已经统一，也不代表篇幅、加粗、图片提示词数量和旧请求处置已确定。不建议只换标签便宣告完成，也不建议先删数据库字段。

## 2. 事实范围与证据限制

本轮核对源码、现役合同和测试断言，没有读取live数据库、凭据、Cookie、token、私钥、运行日志或真实文章。没有调用模型、搜索补全文、图片生成、平台回推或微信推送。

结论是当前文件执行路径的事实，不是生产进程逐模块核验，也不是历史成品逐篇内容判断；没有历史分类比例、实际图片分布或写作转型日期的实测数据。Git HEAD不能单独证明运行进程已加载所有对应文件。

无独立后台研究/审查工具；本文为单智能体源码梳理，不冒称独立双轴审查。

Hermes旧文件名、数据库列名和部分注释沿用历史术语，判断业务时优先看实际提示词、执行分支和字段来源，不能按文件名推断仍是反转写作。

## 3. 治理前完整链路

```text
当前采集批次热搜素材
  → 跨平台事件去重
  → 热点简报选题评分＋判断方向参考＋suggested_form
  → ready素材按既定阶段/逐篇节奏进入Hermes唯一队列
  → 补事件事实上下文
  → form=auto：优先素材suggested_form，缺失才模型判规格
  → 同一事实复盘/客观判断目标下，选压缩或完整正文提示词
  → 正文与新标题、标签、评论、作者拓展
  → 热点简报质检
  → human-writing审改及同一质检复核、文本卫生处理
  → 确定终稿后导语和图片提示词
  → Hermes本地成品保存
  → 原form和兼容reversalScore等字段回推HotNow
  → HotNow保存摘要/完整详情，补素材关联展示
  → 短成品表按旧form显示贴图/反转文
```

自动与人工路径不能混为一谈：

- 自动路径 `_write_and_check` 有原质检重写循环；合格成品定向回推后触发代码制图，制图失败不阻断交付。
- 人工素材写作通过 `_do_write` 调用写作入口，同样进入唯一队列；未过质检的草稿可以按现役合同交付人工审核，不能为了命名统一改成自动路径的丢弃规则。
- HotNow“新建短内容”直接创建人工草稿，没有调用Hermes正文写作；当前仍被强制选择form。
- 历史批量回推与当前定向自动回推的制图策略不同，不能因取消“贴图”标签就改变触发范围。

## 4. 治理前源码证据与语义

### 4.1 已明确转型的业务

| 位置 | 源码事实 | 裁决 |
| --- | --- | --- |
| Hermes `scripts/hotnow/reversal_scorer.py`，`REVERSAL_PROMPT`/`score_reversal` | 判断事件是否值得讲清楚、有无可靠事实与判断空间；明确不能因“不够反转”扣分 | 实际是选题价值评估，不是反转潜力评估 |
| Hermes `short_content_writer.py`，`SYSTEM`/两套正文提示词 | 两套都要求事实复盘与判断，拒绝强行反转、歪曲事实和万能梗 | 共同方向已是热点简报 |
| Hermes `reversal_quality.py`，`QUALITY_PROMPT`/`check_body` | 按标题、事实复盘、判断、原创性/事实边界质检，反差歪曲是失败项 | 实际是内容质量质检，不是反转结构是否成立 |
| Hermes `scripts/prd/公众号写作管线-v2.md`，阶段5.1 | 短内容通过热点简报质检后审改、复检；失败保留合格稿，标题保真分不阻断 | 不能把旧反转PRD作为现役合同 |

### 4.2 form仍在生效的技术分支

| 消费者 | 当前行为 | 后续不能误删的原因 |
| --- | --- | --- |
| `reversal_scorer.py` | 返回`suggested_form` | auto写作实际消费此建议 |
| `short_content_writer.py::choose_form/write_one` | auto优先建议，缺失才判规格，判定失败回退duanwen | 影响模型调用量、检查点和恢复路径 |
| 两套正文提示词 | tuwen约120–260字、1–3处加粗；duanwen约250–600字、2–4处加粗，后者明确事实/判断比例 | 已不是“反转/非反转”区别，但仍改变正文规格 |
| `human_writing_review.py::validate_short_emphasis` | 按form检查1–3或2–4处重点加粗 | 仅改写作提示词会与复检标准冲突 |
| `short_content_pipeline.py::_write_and_check`、`short_content_writer.py::run`、`api_short.py`重写路径 | tuwen生成3条图片提示词，其余1条 | 删除form会改变素材资产数量；提示词不等于已经出图 |
| `comment_generator.py`、`author_extension_generator.py` | tuwen正文上下文截断800，其余3000 | 是上下文预算分支，不是文章内容方向 |
| HotNow `creativeFinishedArticleGenerationRoutes.ts` | 重新生成评论/拓展向Hermes传article.form | 不仅首次生成消费form |
| `short_content_assembler.py::assemble` | tuwen且已有URL时追加图片，其余返回正文 | 当前源码搜索未发现自动主链路调用该assembler；按兼容独立入口处理，不冒称它主导HotNow推送 |
| Hermes `api_short.py`、store/pusher；HotNow请求类型/校验/仓储 | 接受、持久化、转发auto/tuwen/duanwen | 若变更枚举，需跨端兼容和旧任务恢复方案 |

代码制图按`direction=short_content`及既有触发路径处理，不根据表格是否显示“贴图”决定是否制图。两种form都可能有图片提示词；当前自动交付后两种form都可获得代码图片。因此“duanwen纯文字、不配图”的前端说明已不成立。

### 4.3 直接错误的HotNow展示与入口

- [ShortFinishedArticlesPage.vue](../src/client/pages/creative/ShortFinishedArticlesPage.vue)：形态单元格仅判断`record.form === 'tuwen'`；`v-else`统一显示“反转文”。空值、空字符串、未知值和其他来源的数据全部被错误归类。
- [shortFinishedArticlePresentation.ts](../src/client/pages/creative/shortFinishedArticlePresentation.ts)：仍固定“形态”列；“爆文”列由页面显示`reversalScore`，下方趋势条来自素材`trendBreakdown`。
- [ShortSourceItemsPage.vue](../src/client/pages/creative/ShortSourceItemsPage.vue)：自动判断说明仍选“贴图/反转文”，duanwen描述仍为“纯文字反转短文，不配图”；自定义写作共用旧选项。
- [creativeFinishedArticleCrudRoutes.ts](../src/server/routes/creativeFinishedArticleCrudRoutes.ts)：手动短稿接口不提供合法form即400；页面默认tuwen并强制显示两项旧形态。它不经过正文生成，这种选择不代表真实写作判断。
- [router.ts](../src/client/router.ts)和[renderAppLayout.ts](../src/server/renderAppLayout.ts)：短素材入口描述仍为“反转贴文/短文”。
- Hermes `api_short.py::handle_write`仍把duanwen映射为“反转文”写入任务标签；历史队列标签已经持久化，不能批量覆盖。
- [README](../README.md)仍介绍自动判断/贴图/反转文；Hermes `scripts/prd/热讯平台需求-短内容线管理端开发.md`保留旧“铺垫→意外转折→意义”目标和无自动出图设计。

### 4.4 分数、方向和图片必须解耦

| 字段 | 当前来源和真实用途 | 不能做的推断 |
| --- | --- | --- |
| Hermes素材`reversal_score` | 新选题评分，回推HotNow素材`score` | 不等于成品质检，不等于预测阅读量 |
| Hermes成品`reversal_score` → HotNow`reversalScore` | 写作后/最终复检分，自动保存`res.score`，人工保存最终质检结果 | 不等于素材趋势分；不能把所有历史值解释为今日相同评分版本 |
| `trendScore/trendBreakdown` | HotNow关联素材读取；与成品质检是不同来源 | 不应作为reversalScore的构成维度展示 |
| 素材`reversal_angle` | 核心事实重点或判断方向参考，回推时追加到素材summary | 不等于固定写作类型，也不是锁定观点 |
| 成品`reversalAngle` | 平台支持兼容字段，推送器只在输入article带值时发送 | 不能据此构建可靠“写作方向”分类列 |
| `form` | 历史兼容生成规格值 | 不等于文体判定、实际图片状态或写作新旧版本 |
| 图片提示词/图片URL/代码图片 | 计划资产、已生成资产和特定图片产物 | 三者不能互相冒充，也不代表文章是“贴图文” |

补充数据边界：当前Hermes `short_articles`写入和读取没有成品`reversal_angle`列，也未在读取时关联素材补齐；常规`write_one`返回体不含该字段。推送器“支持发送”不等于现役每篇成品一定携带方向。`quality_detail`保存于Hermes本地，当前推送器没有把它作为独立完整质检模型交付HotNow。不能先画方向/质量维度列，再用旧字段猜数据。

## 5. 开发目标与成功标准

1. 用户不再被“反转/贴图”二分误导，未知数据不被默认归类。
2. 展示层分清业务方向、生成规格、质检分、素材趋势、图片状态和来源；不新增无数据支撑的分类。
3. 历史正文、图片、人工稿、分值和任务编号保留；展示纠偏不引发历史改写或重新生成。
4. 所有现役自动/人工任务、质检门禁、推送、制图和恢复行为不因文案治理改变。
5. 代码、用户说明、Hermes现役PRD与兼容合同同轮一致；旧PRD有明确历史标识，不再充当新需求。
6. 统一两套生成规格作为明确的独立开发任务，必须有完整跨端方案与测试证据；展示纠偏通过不等于生成策略统一完成。

## 6. 推荐需求及需确认的决策

### 已可确定的需求

- 成品表撤销“贴图/反转文”的业务分类。**首选移除无业务价值的形态列**，而不是所有行换成固定“热点简报”标签。
- 不依据旧form、正文长度、是否有图或某些关键词重新判定写作方向；不新建模型分类器。
- 成品质量数字展示为“质检评分”，明确历史兼容来源；不宣称爆文预测。素材趋势若保留，独立注明来源，不贴在质检数字下冒充评分拆解。
- 手动空白新建短稿不需要用户选择生成规格；这项涉及接口的兼容扩展，不能仅删页面选项仍保留服务端400。
- 素材模型写作入口不能继续用“反转文/纯文字不配图”描述实际行为；队列新标签、路由说明和README同样纠偏。

以上需求已按本轮授权落实，现役合同同步至README、Hermes边界及对应PRD，验证和发布结果见总体计划。

### 已确认方向与尚待确定的规格

**已确认采用原B方向：取消旧业务二分，新短写统一生成策略。** 统一事实复盘＋判断，由素材复杂度决定表达，不再让历史form决定新稿的正文、加粗、图片或附属文案策略。长文与短内容仍是两条独立业务流程，共用能力而非共用全部阶段。

原A方案仅撤展示分类、保留两套生成规格，不再是最终目标；可以作为分批交付中的展示纠偏步骤，但不得把它当作统一完成。

用户已授权自行锁定并实现：新默认/auto走brief-v1，建议120–600字、1–4处重点、3000字符附属上下文、1条图片提示词；旧显式规格和无标记在途任务原样兼容，不修改历史或schema。评论/拓展在实际交付稿确定后生成，成品质检与素材趋势分列，空白人工稿省略form；旧合法值保留、非法显式值拒绝。具体任务与验证以总体计划为准。

“热点简报”是本文对现役源码目标的总结，不是擅自定义所有人工稿、历史稿或未来短内容的唯一方向。若期望进一步拓宽写作方向，需明确新目标与质量要求；不自行发明新的文体枚举，也不把现有文章全部贴上新标签。

历史评分无可靠版本标记时，显示兼容质检数值并说明按生成时标准；不把历史反转评分批量改为新版本评分。是否新增可审计评分版本字段，只有后续明确需要区分新旧标准才设计，不默认迁移。

## 8. 不可突破的边界

- 长短方向与独立列表保持；长文模式、模型、Provider和标题规则不变。
- Hermes仍是唯一队列/编排真源；人工优先、逐篇节奏、阶段门禁、当前批次、任务编号、取消/让位与重放恢复不变。
- 自动质检重写与人工草稿交付差异、现有各入口阈值不在本次文案治理统一；不得恢复反转门禁。
- 5秒防抖、按文章身份串行最新版、关闭先确认、失败留稿、版本冲突和图片安全合并不变。
- 自动代码制图和人工触发边界、图片失败不阻断、提示词/实际图片/封面选择/微信草稿推送合同不变。
- 原列表分页30条、筛选搜索、全量日期带、软删除/恢复、审核、置顶及鉴权不变。
