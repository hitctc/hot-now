# 短内容科技数码与 AI 方向开发验收

## 1. 已确认需求与边界

- 科技数码与 AI 同为核心方向，非排他；现有其他热搜仍可自动和人工写作。
- 直接使用既有 `juya-ai-daily`、`wechat-rss` 补充短素材，不新增源，不抢占长文 RSS，不补投历史库存。
- 自动选题软优先，不设固定产量或比例；总能力不变时其他热点的实际产量可能下降，不承诺数量不变。
- 新成品标题旁 AI 紫色、科技数码蓝色，带文字；不整行染色、不新增筛选或统计，不影响公众号正文/封面/代码图片。
- 历史成品不重写、不补分类；人工指定素材不替换，投递间隔、质检、重写预算、图片和推送规则不变。

## 2. 实现与职责

1. HotNow `raw-rss` 为两个既有源提供按方向隔离的只读交接，支持 `afterId` 与 `latestId`；长方向默认行为保持发布时间窗口，短方向使用采集时间。
2. Hermes 原短采集批次合并热搜与 RSS。第一次成功读取建立编号基线，不入库存量；之后按编号升序分页，先落素材再推进 `short_rss_after_id`，重放不刷新旧素材时间；失败不跳过未落库编号。该游标是采集位置，不是第二套任务状态机。
3. RSS 保留正文和原来源名称，独立短方向 external ID 不影响长素材身份；长 RSS 读取显式约束 `direction=article`，不评分短素材副本。
4. 复用原选题评分请求识别主领域，在素材 `extra.content_domain` 保存；当批 ready 先按平台轮转，再两篇核心穿插一篇其他，不是固定配额。
5. 新默认/auto 请求冻结 `editorial_focus=tech-ai-v1`。写作同一请求返回主领域，仅对核心稿选择实际变化、用户影响、限制等角度；不增加分类模型调用。旧队列任务缺该参数时保持提示词和恢复输入。
6. 主写作第一步 `stepTrace.meta` 保存领域版本与分类，沿用既有存储和回推；摘要查询只追加两项轻量元信息。表格仅显示显式 AI/科技数码标记，不以关键词或来源猜历史分类。

领域合同为 `ai / tech_digital / other / unknown`。按事件与正文主线识别，每篇一个主领域；科技人物八卦和仅出现 AI 字样的普通热点不归入核心，汽车/医疗/金融交叉内容仅在技术或 AI 应用为主线时纳入。缺失或非法分类归 unknown，不阻断正文交付。

## 3. 验证范围

- RSS 长短互不抢占、URL 锚点去重、严格游标参数、增量分页与采集时间窗口。
- 首次不投历史、两个源均入库、同页重放幂等、请求/落库失败不越过游标、RSS 失败热搜继续。
- 领域识别复用原请求、来源元信息不覆盖、软优先仍穿插其他热点、原批次与队列恢复规则不变。
- 新任务冻结方向、旧任务提示词不变、领域追踪本地保存/回推/成品摘要读取与文字色标。
- 相关 Hermes 隔离测试、HotNow 服务端与前端测试、客户端类型检查、完整构建和差异检查。

## 4. 人工验收待办

当前智能体没有可用的已登录浏览器操作能力。自动测试与健康检查不等于以下人工验收通过。

- [ ] 首次新版本短采集只建立 RSS 基线；之后新采集的两个 RSS 条目可在 `/creative/short-source-items` 看到，来源不显示为热搜。
- [ ] `/creative/short-finished-articles` 新 AI 稿显示紫色 AI、新科技稿显示蓝色科技数码；刷新、分页后保持，旧稿无新增领域标签。
- [ ] 桌面和移动端标签不遮挡标题、素材入口、日期分组和操作按钮。
- [ ] 阅读少量真实新成品，确认科技稿有具体用户影响/限制，不编造评测；其他热点没有被强套科技视角。
- [ ] 同一 RSS 仍可供长文使用，自动短写保持原投递节奏。

这些是上线后观察项，不以真实模型额外生成或人工推送替代用户验收，不修改历史数据凑验收样本。

- 规范轴自审：保持 Hermes 唯一队列/编排，HotNow 只读交接与展示；不迁移数据库、不接触 live 数据、凭据或历史成品，不顺手重构。摘要只返回两项领域信息。
