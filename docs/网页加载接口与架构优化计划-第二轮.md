# 网页加载、接口响应与架构优化计划（第二轮）

日期：2026-10-03。参考版本：`b6502328099a135ad4fc068403ce2e21b7a7ebcc`。

**状态：P01–P12的评估、最小实现、完整门禁及安全生产部署已完成，进入单次提交推送。** 实际测量、失败/限制和发布证据唯一记录于[性能优化基线](./性能优化基线.md)的第二轮章节；未实施候选不能冒作收益。

## 1. 结论与目标

下一轮先建立页面和完整接口的真实分段基线，优先解决经测量确认的关键路径、重复工作和层次边界问题，不继续以行数、分包名称或查询计划中的某个关键词为优化目标。

三个方向：

1. 页面打开与加载：降低进入页面到首批有效内容可见的时间，兼顾冷访问、站内切换、首次详情及暖重开。
2. 接口响应：减少读取、计算、映射、序列化及上游等待中的可消除成本，同时避免单请求加速却拖慢其他请求。
3. 代码架构：保持模块化单体，以稳定业务职责划界，形成可测试、可维护的单向依赖，而非换技术栈或扩大抽象层。

**所有现役功能、输出、权限、数据新鲜度及任务恢复合同不变是硬门禁。** 性能收益是需要实验验证的条件，不是以牺牲功能达成的承诺。

本文是完整候选及决策计划。必做项是建立证据、冻结行为、评估、回归和记录；条件项只有证据支持且风险可控才改代码。“完整实施”包括有依据地保留，不等于所有候选都必须实现。

## 5. 测量设计：先回答慢在哪里

### 5.1 页面与用户场景

- 内容：`/`、`/ai-new`、`/ai-hot`，首屏、筛选/搜索、追加加载。
- 创作：`/creative/source-items`、`/creative/short-source-items`、`/creative/finished-articles`、`/creative/short-finished-articles`；首次进入、翻页、筛选、深页和详情。
- 编辑器：冷首开、暖重开、A→B、加载中关闭、失败恢复、手机最新预览、桌面三栏、保存失败后重试。
- 其他：`/daily-digest`、`/monitor`、四个 `/settings/*` 现役入口。
- 兼容：`/history`、`/reports/:date`、`/control`及下架页面仍运行的API/feed，重点合同回归，不默认扩展性能重构。

记录用户动作到首个反馈、首批真实数据可见、完整关键区可操作三个时间；不能只计空壳或加载动画。分别记录导航/首字节、资源传输、JS解析执行、数据等待、DOM更新、布局和长任务。公共内容可记录LCP，工作台以实际有效内容可见为主，不能由静态标题冒充加载完成。

冷缓存、暖缓存、站内跳转分开；首次详情模块与数据谁先到分开；正常加载与故障注入分开。桌面/手机仿真/真实手机分开，固定浏览器版本、视口、CPU/网络条件及数据集。仿真只说明该条件，不替代真实设备。

入选性能优化的关键场景，每个前后条件预热5次后采样至少30次，重复3轮；昂贵的浏览器冷场景达不到样本要求时报告单次/范围及不足，不能标P95达标。其他页面做覆盖性浏览器回归，不要求每页机械重复同样的90次性能实验。

### 5.2 接口矩阵

| 入口 | 参数/数据维度 | 需要拆分的阶段 |
| --- | --- | --- |
| `/api/content/ai-new`、`/api/content/ai-hot` | 默认/多来源/子账号与关键词/空选择/搜索/排序/不同页；现有筛选头均纳入 | SQL读候选、评分/归一化、去重排序统计、卡片构建、序列化 |
| `/api/creative/source-items`、`/api/creative/finished-articles` | 长短方向、摘要/完整、30条与合法其他页大小、状态/日期/删除、深页及正文搜索 | COUNT、列表、日期带、关联、JSON映射、序列化 |
| 两类创作 `/:id`、日报列表及 `/:id` | 小/长稿、丰富步骤/图片元数据、有无关联、404 | 详情读取、关联、映射、传输与浏览器处理 |
| `/api/settings/sources`、`/api/settings/profile`、`/api/settings/view-rules` | 账号/来源规模、权限、空数据、后台写入后读取 | 依赖读取、工作台聚合、映射、序列化 |
| `/api/creative/write-queue/status`、现役监控GET | 空闲/活动/历史、冷/热缓存、慢/失败上游、多消费者 | 上游等待、本地补齐、序列化；状态新鲜度单列 |

每个入口核对真实路由、客户端参数与权限，不只测直接repository。隔离HTTP调用使用真实Fastify注册和合成数据库；不把绕过鉴权、映射和序列化的SQL耗时标为接口耗时。

SQL预热5次、至少30样本×3轮；入选接口主验收每关键参数档至少100请求×3轮，分别记录冷/暖、并发1/2/4的P50/P95/最大值、错误率及字节。所有请求和失败纳入记录，不剔除慢请求或只挑成功请求；成功与错误耗时另列。串行先行，有限并发只在隔离环境；不对生产压测。记录事件循环延迟及其他轻量读取的等待，避免局部加速掩盖整体阻塞。

P01结束后锁定代表性参数与瓶颈场景，不对全部参数做笛卡尔积重复压测。每次实验设有界请求超时、样本上限与资源停止条件，超限保存失败证据而非无限重试。隔离服务优先用现有Fastify注入/测试装配，不启动包含真实采集、发信和任务调度的运行入口；需要浏览器HTTP监听时同样只接合成依赖并阻断外网。

合成规模以5千/2万/10万条内容、丰富正文/JSON、深页与历史形态覆盖，不把这些数量描述为当前生产。需要真实分布时补验证副本，不能只用均匀小字段数据判定收益。请求与结果仅本地比对，报告只留汇总、哈希、规模和脱敏路径，不保存正文、搜索词、身份信息或原始HAR。

### 5.3 归因与预算

1. 本地SQL/CPU慢：先查扫描、重复计算和映射，不先加缓存。
2. 上游慢：保留现有超时/错误，报告边界；不能以增加TTL或假成功“加速”。
3. 网络/资源慢：核对真实依赖、压缩、缓存、首开与总下载，而非只看chunk大小。
4. 渲染慢：检查节点、重复渲染、布局/深响应性，不能只测函数时间。

建议实验预算：关键列表有效首屏P95≤1秒、筛选/翻页≤800ms、正常详情首开≤1秒；隔离本地读取接口争取P95≤200ms。它们是待基线校准的预算，不是跨网络/设备承诺，也不适用于模型完成或Hermes上游等待。超过预算必须归因；已经很快的接口以不回退和低复杂度为主。

在相同场景中，性能变更至少超过重复实验波动；候选参考门槛为关键耗时改善≥15%且≥20ms，或关键启动压缩依赖减少≥10%，或明确消除重复读取/长任务。门槛不是要求所有优化同时满足；小于门槛只记录“未证明可见收益”，不为凑比例改功能。架构重构可以无速度收益，但必须说明职责/测试收益，并保证行为及性能不回退。

## 6. 页面打开与加载候选

### P02：按领域装配组件库（条件实施）

目标：`antdComponents.ts`、`main.ts`、`router.ts`、实际页面/壳层组件，必要时 `vite.config.ts`。

- 先记录公共内容与创作/设置的真实启动依赖，确定Table、DatePicker、Form等是否成为不必要的公共页启动成本。
- 对比保持现状、少数重族页面局部注册、稳定领域装配三种方式；首选最少改动的局部方案。不建立通用动态插件系统。
- 壳层和全局提示、StyleProvider/主题必须先可用；子组件解析不能依赖已经访问过其他页面。重复装配须幂等，无生命周期/样式重复。
- 所有公共导入和确认分支都检查，避免动态命名空间导入重新拉整库；不单靠分包名称或文件数判定收益。
- 冷直接链接、登录后跳转、切换主题、表单校验、日期/选择/表格/弹窗、首次失败恢复均覆盖。
- 若共享vendor仍拉全部依赖、首开明显变慢或实现必须大范围重写，保留当前注册。禁止以未核实的“按需一定更快”替换现役实现。

### P03：关键加载链与有限预取（必做测量，条件实施）

目标：壳层、页面挂载读取、两个Lazy详情及对应数据service。

- 画实际请求/模块依赖链，区分需要先获身份/编号的串行步骤与真正无依赖步骤；页面数据不能因队列、统计或账号摘要慢而无谓等待。
- 模块与GET并行仅在事实支持时使用，保留有效编号、权限和旧响应保护。已在并行的不重复改。
- 条件评估用户明确意图触发的少量模块预取；默认不预取业务详情、不猜下一文章、不让公开页发私有GET。
- 手机触摸、节省流量、快速掠过链接、失败模块缓存及发布后旧页面必须考虑。没有首开收益就不加预取。
- 保留立即反馈、加载可关闭、关闭留稿、任务恢复和确认后重载。不自动刷新页面，不预执行保存/模型/推送。

### P04：重复读取与读取所有权（必做审计，条件实施）

目标：壳层/profile页、监控实际消费者、成品页多个watch/手动刷新及现有service。

- 确认同参数请求确实重叠且有成本，再局部合并；优先复用既有2秒客户端队列缓存及专用单飞，而非创建全应用数据缓存。
- 可复用的仅为白名单安全GET；键含路由、实际query/筛选头、权限上下文与会话世代。不能把同URL不同筛选共享，也不能跨退出/重新登录复用旧在途结果。
- 在途复用完成立即释放；失败不常驻。消费者取消只撤自身等待，不能让一个AbortSignal取消其他有效消费者；过于复杂则保留独立请求。
- 写入后的手动刷新必须获得足够新的结果，不能复用写前读取；dirty设置草稿不被读取覆盖。
- `Promise.all`不让同步SQLite并行；没有独立异步依赖的证据，不机械并行所有await。

### P05：渲染和响应性成本（条件实施）

目标：内容追加列表、创作表格、步骤追踪及编辑器现有计算边界。

- 按实际节点数、长任务、更新次数与对象规模决定优化；当前30条表格不能默认虚拟化。
- 优先稳定key/props、已有展示派生结果复用、只展开时构建昂贵追踪展示，以及真正不可见区不计算。
- `shallowRef`只在全量替换且不依赖嵌套修改的状态使用；写入/排序/推送状态更新逐一核对，不能为少响应性造成界面不更新。
- 长列表虚拟化仅在持续追加确有DOM瓶颈且现有依赖能可靠实现时评估；动态卡片高度、滚动锚点、查找/复制、加载触底与无障碍必须等价。不新增依赖作为默认方案。
- 编辑器已有手机免计算与串行保存，默认不重写；禁止无界全文缓存、改变解析输出或保存节奏。

## 7. 接口响应候选

### P06：完整候选管线的重复工作（优先测量，条件实施）

目标：`core/content/buildContentViewSelection.ts`、`buildContentPageModel.ts`、评分/排名/来源范围与展示帮助模块。

- 分别测SQL读正文/元数据、规范化、评分、映射、排序去重、来源计数和最终分页，确认哪一段主导。
- 优先同一请求内共用referenceTime、复用重复解析/规范化、避免未使用的昂贵展示派生；若尝试只为最终页构建展示字段，先列清评分、去重、排序和来源统计实际需要的全部字段。
- 不把标题搜索下推到候选评分前，不提前切片；排名/去重的胜出卡片和总数可能因此改变。正文关键词与元数据来源信息必须完整参与。
- SQL预过滤只有对所有规则开关、来源计数、时间格式、排序及去重证明等价才可采用；未证明就继续完整候选集。不得建立第二套近似评分算法。
- 分页结果、顺序、徽标、分值、来源计数和空态逐字段对比，时钟固定；同URL/语义重复、跨来源、非法日期、24小时边界、规则切换及子来源关联全覆盖。
- 默认无跨请求缓存。时间相关排名/规则/反馈/采集修改使失效复杂，不能用任意TTL“优化”。

### P07：创作列表读取、映射和搜索（必做分析，条件实施）

目标：`creative*ReadRepository.ts`、`creativeListRoutes.ts`、现有列表service及相关测试。

- 分参数分别测COUNT、分页排序、全量日期带、关联查询、JSON派生和HTTP序列化，不能以057收益推断所有接口已快。
- 已有摘要、分页和关联批量读取保留；评估去重后的关联ID和安全分批只读，不把一次批量查询误报N+1。
- 审计同一响应内重复JSON解析，但不能改变对象所有权、错误语义或丢失完整详情字段；列表已有51字符预览与步骤时间派生，不能未经合同检查继续缩短。
- 深页OFFSET、正文LIKE和排序表达式单独取查询计划，已有索引命中/低成本则保留。不能换游标分页、FTS或限定搜索范围；当前接口合同禁止这些变更。
- 索引实验只在副本/临时库进行。必须对现役索引去重，比较结果、构建/磁盘/插入和更新成本、锁持有、迁移事务/幂等/历史日期/完整性。表达式/生成列的历史数据风险不足以解释时，不实施。
- 日期带继续全量读取原有过滤口径，文章/日报/旧空类型推送日志保持区别；不从本页或有限history推导统计，不物化增量计数。

### P08：设置工作台与Hermes代理归因（必做测量，条件实施）

目标：来源工作台SQL、设置视图适配、监控代理与既有读取器。

- 来源页保留现有独立来源统计SQL，不改用页面排名统计。测重复扫描和关联索引后，再评估同一次读取的聚合合并；合并不能影响三个视图的不同时间范围/可见比例。
- 设置多项依赖只有独立异步等待时才并行，失败降级、状态读取时点和写后新鲜度保持。CPU/同步库耗时不靠Promise.all解决。
- Hermes接口报告上游/本地耗时，维持既有超时、状态码和失败内容。GET在途合并仅按P04白名单、权限、参数和写后刷新门禁评估。
- 禁止新TTL掩盖上游等待、改变队列降级、绕过Hermes、猜空闲或自动重试任务创建/取消。超出HotNow可控制范围只记录，不扩大为Hermes改造。

## 8. 架构方案：模块化单体、稳定职责、最小抽象

目标方向继续为：

```text
页面（用户操作编排）
  → 展示组件 / 同域组合式函数（状态、生命周期）
  → service（类型化协议与读取所有权）
  → HTTP适配（鉴权、参数、错误、响应）
  → core领域读取/动作（业务规则、数据补齐）
  → repository / 已有外部客户端（持久化/上游访问）
```

这是现有规范的深化，不创建新的全局架构。页面与展示的分工应按稳定业务区域判断；组合式函数不是把全部脚本平移后任意扩大的容器。路由不持有领域SQL，core不依赖Vue/Fastify或HTTP请求，repository不管理弹窗和队列业务。运行时装配仍由main/app与createServer完成。

### P09：创作读取的领域边界（明确结构候选）

目标：`server/routes/creativeListRoutes.ts`及承接其列表/详情关联补齐的现有core模块。

- 将关联补齐、摘要/完整模式组装、来源名读取归入实际领域读取职责；优先扩展职责吻合的现有模块，必要新模块待边界确认后命名，不为每条SQL建文件。
- HTTP层仍唯一执行session/token鉴权、原参数解析、503/404与reply发送；不把协议验证的兼容变化夹带进重构。
- 类型化依赖只包含所需db/读取方法，不复制巨大ServerDeps、不引入通用repository基类或依赖注入容器。
- 路由和领域读取用同一合成数据库逐字段比对；source-names权限、空关联、重复关联、summary/full、错误JSON/历史数据语义均保持。
- 此项结构收益可独立成立，不冒称迁移文件后请求自然变快。

### P10：长短成品页的稳定功能区（明确结构候选）

目标：`pages/creative/FinishedArticlesPage.vue`、`ShortFinishedArticlesPage.vue`及现有同域展示模型/组合式函数。

- 先建立状态所有权图：列表查询/筛选持久化、详情身份、审核动作、推送协调、手工创建分别由谁拥有。
- 优先提取查询/筛选生命周期和详情读取两个完整职责，页面保留跨区域用户意图编排；审核/推送仅在职责混杂且可独立测试时提取。
- 复用现有短成品展示模型和详情/保存工作流，不再创建第二保存器、任务恢复器或图片协调器。
- 两页保持独立业务入口与状态门禁；共享只限已证实一致的纯展示/查询机制，不抽象带大量布尔参数的“万能成品页”。
- props/emits、表格列、移动固定列、筛选草稿、审核/删除/置顶/状态更新、刷新与编号恢复逐项不变。
- `settingsApi.ts`、`createServer.ts`、851行文章协调器及稳定测试文件无职责证据则保留。新增超千行清单须同次完整治理，不临时按行数压缩。

### P11：依赖与合同守卫（必做审查，条件补轻量测试）

- 对实际治理范围验证展示层无HTTP编排、core不反向依赖client/server/Fastify、兼容API导出唯一、缓存和状态没有复制实例。
- 仅为已经成立的边界添加最少的导入/公开接口测试；区分运行态/类型/纯函数，避免一刀切规则误伤合法装配。
- 使用现有TypeScript、Vitest及构建器，不新增架构扫描平台、规范框架或CI依赖。
- 方法注释说明输入/输出、副作用与边界，复杂异步分支解释原因；删除本轮迁移产生的死导入，不清理预存兼容代码。

## 11. 验收、停止条件与发布

### 11.1 单项决策记录

每项保留：候选 → 当前事实 → 基线/分段 → 至少现状和最小方案对比 → 业务风险 → 实施或保留 → 前后同条件结果 → 回归/未验收项。无热点可保留，缺测量不能写“无需优化”，没有收益不能写“已提速”。

### 11.2 实施门禁

1. 固定接口、数据与状态所有权，建立受影响测试基线；缺陷先复现，重构前后同断言。
2. 最相关测试先行；客户端改动检查类型并构建，服务端/装配/迁移改动完整构建。
3. 最终整体源码状态运行 `npm run test`、`npm run typecheck:client`、`./node_modules/.bin/tsc -p tsconfig.json --noEmit` 和 `npm run build`，并做差异/链接/规模/依赖检查。构建清理dist及其他有状态命令事先说明精确范围，遵守安全授权。
4. 同条件复测入选场景及相邻页面/接口，并发下无错误率或关键尾延迟回退；差异超出基线波动需解释或撤回。
5. 浏览器与真实设备分别标状态；核心保存、鉴权、任务恢复或统计正确性未证实则阻塞，不以测试/健康检查替代现场验收。
6. 规范和需求两轴审查；无法独立审查则注明自审。文档和代码同轮更新，证据只归性能基线，不给AGENTS追加流水账。

出现业务结果不同、取消/重放风险、跨身份泄漏、无法解释日期/排序变化、未保存稿可能丢失、需要新依赖/跨端协议或共享Nginx改动时停止，不为优化目标自动扩大授权。

### 11.3 后续实施时的交付

本轮执行授权包含发布。实际发布仍用 `./scripts/deploy-prod.sh --wait-hermes`，保留既定快照、构建、部署、健康检查和停前自然等待；未知/失败不当空闲，只重启受影响HotNow，不重启Hermes。
