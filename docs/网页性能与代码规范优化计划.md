# 网页性能与代码规范优化计划

日期：2026-10-03。状态：完整开发、整体验证与生产发布完成；本轮以单一完整提交交付，提交推送实际结果以Git远端和最终报告为准。证据见性能优化基线。

## 1. 目标、执行方式与权威入口

本计划一次定义 HotNow 网页性能和相关代码规范治理的完整开发范围，后续按依赖顺序连续完成开发、验证、验收和交付，不再只规划首批，也不把大文件治理拆成多个开发批次或多个提交。下面的工作项是同一次开发的任务分解，不是多次立项或分批发布。

目标：减少不必要的首屏下载、后台请求和重复计算，降低经实测确认的服务端读取成本，同时让请求、状态、领域读取和展示各归其位。现有业务、数据、接口、保存结果和自动化合同不变。

- 长期规范以 [开发与模块化规范](./开发与模块化规范.md) 和 `AGENTS.md` 为准；本文不创建另一套规则。
- 性能基线、实验结果和最终发布证据写入 [性能优化基线](./性能优化基线.md)，本文只维护范围、任务状态和验收结论入口。
- Hermes 合同以 [Hermes 自动化协作边界](./Hermes自动化协作边界.md) 为准；发布遵循 [生产部署手册](./生产部署手册.md)。
- 本次制定计划只写文档，不修改业务代码、不部署。后续收到执行指令后按完整范围推进；只有范围变化、安全授权不足或核心正确性阻塞时再次请求确认，不为每个工作项重复规划。

“完整执行”指所有必做项完成，所有条件项完成评估并有实施或不实施的证据，所有验收项有真实状态；不意味着所有候选都必须改代码，更不意味着把待浏览器验收写成通过。

## 3. 不可突破的业务与安全边界

1. 保持单进程、SQLite、文件归档和现有聚类架构；不引入新的服务、队列、调度器或状态机。
2. Hermes 继续是自动写作、图片、计划、重试和告警的业务编排真源；不改变模型、Provider、调度时间、短内容节奏、任务优先级和取消合同。本计划不修改 Hermes 源码，也不默认重启 Hermes。
3. 正文自动保存继续防抖、串行和只提交最新版；手动保存、关闭收尾、推送前保存、文章切换和失败后的未保存内容不得丢失。不能为了减少请求而跳过应保存的编辑。
4. 图片回写只合并图片结果，不用任务旧正文覆盖当前人工稿；图片失败不阻断文章。主题切换原有持久化语义不变。
5. 日报同日期覆盖、请求编号恢复、跨午夜素材日期、版本冲突保护、旧日志空类型兼容、文章与日报推送统计区分全部保留。
6. 内容页保持完整候选集过滤后每页 50 条切片、既有筛选/排序/搜索/持久化与无限加载语义；创作列表保持摘要读取、默认 30 条分页和详情按需加载。
7. 前台状态刷新间隔不擅自改变；暂停的是非必要后台读取，不是服务器业务执行。排队时长不成为新的模型超时依据；素材溯源既有 90 秒观察超时保留。
8. URL、HTTP 方法、鉴权、参数、响应、错误和兼容导出默认冻结。请求取消仅可用于失效的安全读取，不取消业务写操作或已受理任务。
9. 不读取凭据、生产 live 数据库或私钥，不输出正文、Cookie、token 或请求体。合成数据为默认；如确需生产副本，使用项目既定工具和独立目录获取验证副本，不覆盖现场、不扫描敏感配置表。
10. 不调用真实模型、微信推送、生产生成或批量业务操作验证性能；不新增外部遥测、不升级依赖、不手工改锁文件、不直接编辑构建产物。
11. 生产浏览器切换主题、编辑正文、生成、取消和推送可能有写副作用，不能伪装成只读测量。写操作验收默认放在隔离环境；生产业务写验收须另获确认。

## 5. 各项实现边界

### W01：基线和行为冻结

- 更新全部 `src/`、`tests/` 超千行清单、展示组件实际请求清单及当前可访问路由；不恢复已下架 AI 时间线页面。
- 重新构建记录 HTML 直接引用及模块预加载资源，并用浏览器核对入口实际依赖；原始、gzip 与实际网络传输字节分别记录，去重，冷暖缓存分开。
- 浏览器覆盖现役内容页、长短素材/成品列表、文章详情、日报、监控和来源/公众号配置；旧页重点做 CSS 兼容。具体 URL 从 `router.ts` 和服务端注册读取，不猜路径。
- 统一环境、数据集、缓存状态和计时口径。SQL/渲染实验预热 5 次后采样 30 次、重复 3 轮；明确是否包含 prepare、映射、序列化和 DOM 更新。浏览器不足 30 个样本只报告单次或范围，不称为可靠 P95。
- 记录首屏、详情首次/再次打开、长文输入、预览、网络请求数、在途请求数、统计读取成本；不增加常驻监控系统。
- 记录相关行为测试基线；新增性能记录只保存合成规模、时间、大小和脱敏路由，不保存业务正文或未脱敏 HAR。

### W02：异步身份保护

目标文件：`src/client/components/content/useContentFeedPageController.ts`、`src/client/components/creative/ArticleDetailDrawer.vue` 的素材封面读取及其相关测试。

- 先用实际组合式函数/挂载组件及受控延迟请求重现，不仅保留 AST 实验。覆盖筛选 A→B、搜索、排序、首次加载与刷新重叠、旧追加结果跨查询返回。
- 复用现有 `src/client/utils/latestRequestGuard.ts`；仅在确需终止失效 GET 时考虑现有 `latestAbortController.ts`，不新建平行守卫。
- 当前请求身份同时保护列表、分页、URL、默认筛选持久化、错误与 loading 收尾。旧请求不能关闭新请求的加载态，也不能留下永不清除的追加状态。
- 封面请求覆盖 A→B、A→无素材、关闭和卸载；响应只关联仍有效的素材身份，旧失败不能清空新封面。
- 修复的是用户最后一次有效选择的结果，不更改排序策略、数据筛选、分页数或操作入口。若完整组件实验未能确认缺陷，保留测试与证据，不凭猜测改代码。

### W03：首屏加载

目标文件：`src/client/main.ts`、`src/client/layouts/UnifiedShellLayout.vue`、`src/client/components/creative/WriteQueueStatus.vue`、当前详情入口及必要的 `vite.config.ts`。

- 盘点所有 `a-*` 组件、指令、全局配置和函数式 `message`/`Modal` 使用；评估现有依赖内的显式按需注册/局部导入，不默认安装自动导入插件。
- 保留主题、图标、弹窗、表单校验、表格、移动布局及全局配置。不能只验证首页而漏掉设置、监控、日报或详情内部组件。
- 详情、编辑器、素材弹窗按实际入口延迟加载；检查手工分包是否把本应延迟的依赖重新拉入首屏。只在依赖图支持时调整分包，禁止为了告警好看而任意切包。
- 首次异步挂载时 `open=true` 且文章已返回，现有非立即执行的初始化监听可能不触发，必须补等价初始化测试和必要实现。
- 模块延迟下载与组件关闭/销毁分开：保留关闭收尾、任务观察、未保存状态和事件监听清理，不直接用 `v-if` 销毁替代既有生命周期。
- 加载失败有明确提示和可再次尝试的入口，不把失败缓存成永久不可打开。是否预加载由冷首开测量决定，不默认把全部详情又提前下载。

### W04：轮询和共享读取

重点范围：`MonitorStatsCards.vue`、`MonitorSwitches.vue`、`CodexTaskQueue.vue`、`CodexConsumption.vue`、`MonitorPage.vue`，以及实际挂载的其他观察入口。

- 隐藏时不发起新的非必要周期 GET；已有在途请求可正常结束。恢复可见后及时刷新，避免等待完整周期。
- 同一读取通道至多一个在途请求；相同参数、鉴权上下文下的并发消费者可以复用同一请求，手动刷新不返回过期快照。
- 不为减少次数新增长缓存。复用现有队列客户端 2 秒、服务端 15 秒缓存及明确降级标记，保留原错误提示和上次成功状态，不把错误显示为空闲。
- 组件卸载后无定时器、事件监听或迟到回写。配置编辑期间保留 dirty 草稿，后台读取不得覆盖用户尚未保存的输入。
- 对 `usePipelineStatus.ts`、`MonitorPlatformStats.vue` 等先确认消费者；未使用者不算运行开销，不为它们新建全局轮询。不顺手删除兼容入口。
- 素材溯源逐项读取只有在真实请求数/重复证据支持时优化；保留观察超时及终态语义，不额外创建服务端批量业务流程。

### W05：编辑器与预览

目标文件：`ArticleDetailDrawer.vue`、现有 `article-detail/` 组合式函数、`ArticleMarkdownEditor.vue`、`services/wechatRenderer.ts`。

- 先测输入到可见更新、渲染调用次数和耗时，分别覆盖手机仅人工稿、独立全屏预览、桌面三栏。
- 优先让实际不可见预览不随每次输入重新计算；重新打开预览或显式保存/推送时必须使用最新文本和主题。
- 如确需合并重复预览计算，只处理可丢弃的展示中间态，不能对正文保存、主题持久化或推送数据使用陈旧结果。
- 缓存若确有收益，键必须包含文本、主题及实际渲染选项，并限定保留范围；不保留无界全文缓存，不引入新的渲染引擎或 worker。
- 输出 HTML、图片占位符、源码行追踪、标题同步、导语和人工稿处理保持一致；手机不恢复隐藏的 AI 草稿/预览栏，桌面不减少现有栏位。
- 保存工作流只在本项确需调整时修改，保留最新串行队列和版本/文章 ID 保护，不借机重写已正常工作的自动保存。

### W06–W07：服务端读取与查询成本

重点文件：`src/server/routes/hermesOperationalRoutes.ts`、`src/server/hermesWriteQueueStatus.ts` 及承接该域的 core/repository。新模块命名在明确职责后确定，不为每条 SQL 建文件。

- 先建立同一合成数据库下的路由响应等价测试，再将日期统计、历史补齐、成品/素材关联移入稳定的读取职责；路由保留鉴权与 HTTP 适配。
- 合并可验证的重复关联读取，避免逐任务重复查询相同外部标识。外部标识有多个匹配时仍不猜平台素材 ID，不能拿 Hermes 本地编号充当平台 ID。
- 对缓存返回的 Hermes 数据按现有所有权核实是否共享可变对象；本地补齐不得污染后续请求或累加重复历史。若确认问题，只处理该展示数据边界。
- 日期带仍由全量库统计，不从有限 history 推算；保留 `collector_timestamp` 回退、UTC+8、删除过滤、历史补齐上限和排序。无效日期不擅自归入今日。
- 三项聚合和历史排序分别记录 `EXPLAIN QUERY PLAN`、耗时及响应成本；推送统计评估保持文章/日报与旧空类型口径，不改变既有正确查询。
- 索引只在前后对比证明收益、写入成本可接受时新增后续独立迁移；不修改历史迁移 SQL，不因为排序有表达式就重复建索引。
- 缓存不是默认方案。只有能完整覆盖当前写入口的失效机制、满足原新鲜度且显著有益时才实施；不能用任意 TTL 换取统计变旧，更不能新增增量计数状态机。
- 在相同环境中无可重复收益或已有成本很低时，明确保留原查询；分层治理可以完成而不强行“优化”SQL。

### W08：固定范围的分层与大文件治理

实际网络请求编排移出范围（执行前核对现役调用，保留行为与接口）：

| 域 | 组件 |
| --- | --- |
| 内容 | `ContentHeroCard`、`ContentStandardCard` |
| 创作 | `ArticleDetailDrawer`、`ArticlePerformanceFeedbackModal`、`ArticlePushConfirmModal`、`ArticlePushFloatWidget`、`ArticleReviewModal`、`DailyDigestDetailDrawer`、`ImageActionModal`、`SourceItemDetailModal`、`WriteQueueStatus` |
| 监控 | `CodexConsumption`、`CodexTaskQueue`、`MonitorItemsTable`、`MonitorPlatformStats`、`MonitorRunsTable`、`MonitorStatsCards`、`MonitorSwitches` |
| 公众号配置 | `WechatMpAccountModal`、`WechatMpSettingsPanel` |

- 将查询、提交、轮询、异步身份与相关状态放入现有或必要的同域组合式函数；展示保留 props/emits、原事件、loading/error 和 `data-*` 锚点。
- 纯函数、类型、常量、渲染帮助函数和 `HttpError` 类型判断不一律迁移。不要为规避导入检查建无职责的 service 转发层；新注释说明职责、关键参数/返回值和副作用。
- 不机械合并浮窗与确认弹窗、长文与短内容的独立状态，不抽象一个带大量布尔参数的万能工作流。
- `creativeApi.ts` 按现有素材、成品编辑、模型任务、图片、发布及自动化/队列等稳定职责组织；类型跟随所属域，保留原公共导出兼容，避免循环依赖和重复队列缓存实例。
- `site.css` 按原连续区块拆分，显式固定顺序由 `sitePageAssetHelpers.ts` 拼接；仍只请求 `/assets/site.css`。开发和构建运行路径、MIME、回退行为及原响应字节保持一致，不能增加 CSS `@import` 网络请求或重排层叠规则。
- 两个超千行文件在同一次治理与同一完整提交中完成。若执行前出现新增超千行文件，先说明职责与范围差异，再确认清单，不静默扩大重构。
- `settingsApi.ts`、长短成品页、`useArticleImageWorkflow.ts`、`createServer.ts` 等低于阈值者只改本计划直接涉及的区域；没有职责证据不继续拆分。

### W09：静态资源和浏览器复核

- 检查首次/重复访问的压缩、长缓存、hash 更新、模块预加载、旧缓存页面遇到新版本资源的错误反馈；不降低现有缓存策略，不把所有资源无条件缓存一年。
- 检查应用入口、延迟详情和旧页 CSS；已存在的缩略图、延迟原图和低优先级加载不重复开发。除非测量证明新热点，不加入新的图片/字体优化范围。
- 对 HTTP/2 用公开 ALPN 和已授权的目标配置检查确认实际链路；单次 HTTP/1.1 结果不构成修改理由。仅在证实源站配置缺口且有收益时考虑现有 `scripts/enable-nginx-http2.sh`。
- Nginx 调整可能影响其他站点，须说明具体配置、命令、影响范围并确认，先验证配置再 reload；鉴权或授权不足时只记录结果，不把网络调整捆绑进普通应用发布。
- 无可用浏览器能力时不重复连接/登录或绕过鉴权；保留最短操作清单、入口与通过标准。布局/体验待验收可依规则如实交付；安全及核心正确性未证实则阻塞发布。

## 6. 性能成功标准与条件项决策

| 指标 | 标准 | 未达成时 |
| --- | --- | --- |
| 首屏资源 | 同一构建统计口径下，去重后的启动依赖 gzip 体积争取较复测基线下降至少 30%；核对真实浏览器没有补下载同等体积 | 如实报告差额和原因，不牺牲功能、不用分包名称掩盖入口依赖；是否缩小目标需确认 |
| 详情加载 | 点击立即有明确反馈；冷首开与暖重开分别比较，不能以无界等待换首屏下降 | 调整加载边界或撤回有回归的方案 |
| 轮询 | 页面隐藏后不再新增非必要周期读取；各通道至多一个在途请求；恢复立即启动有效读取或复用在途请求 | 假计时器与组件测试必须通过，否则不交付 |
| 编辑器 | 不可见预览不做无效重复计算；可见输出与基线一致，输入和保存无回归 | 无热点则保留实现；无法证明语义等价不实施 |
| 查询 | 对实施的性能方案，在固定数据/环境下获得可重复收益，同时结果、日期口径和新鲜度等价 | 无收益不加索引/缓存；性能目标不能替代正确性 |
| 结构 | 固定组件范围的 HTTP 编排归位；大文件清单完成；新增职责可独立验证 | 不以行数下降或空转发层冒充完成 |
| 生产 | 标准部署成功、服务健康、关键入口正常、SHA 一致，待验收单列 | 发布失败停止提交推送，保留现场 |

所有条件项必须记录：候选 → 测量/合同 → 方案对比 → 实施或不实施 → 验证结果。缺测量不能写“不需要”，未实施也不能写“已优化”。不将历史的 50% 接口目标直接套用到当前已经很快的列表。

## 8. 最终验证门禁

1. 每个行为改动先补对应测试；已确认缺陷先出现可重复失败再修复。纯重构以改前/改后等价测试证明。
2. 局部测试通过后，在最终整体源码状态执行 `npm run test`、`npm run typecheck:client`、`./node_modules/.bin/tsc -p tsconfig.json --noEmit` 和 `npm run build`。
3. `npm run build` 当前包含 `rm -rf dist`，只清理仓库构建产物；执行前说明准确命令、影响并依安全规则确认，不把它称为只读检查。
4. 执行 `git diff --check`、文档本地链接检查、全量超千行扫描、固定范围的实际 HTTP 导入/调用复核；验证 CSS 字节和资源行为。若有迁移，补专项门禁。
5. 在相同环境复测性能，记录原始数据、统计口径和不实施决定；不能将合成实验写成线上 P95。
6. 做规范与需求两轴审查；有独立审查工具则使用，没有则明确为自审，不冒称双智能体审查。
7. 浏览器验收与测试/健康检查分别记账。缺少浏览器能力时列待办；核心保存、初始化或鉴权仍存在未解释风险时停止发布。

同一源码状态已有充分证据时不无意义重跑；最终改动若使原证据失效，重跑受影响门禁。Browserslist 的既有数据过期提示单列，不为消除提示擅自升级依赖。

## 9. 文档、部署、提交与回滚

- 开发完成后更新本计划任务状态，原始性能及发布证据归入 `性能优化基线.md`。目录/职责变化写入 `开发与模块化规范.md`；只有可见功能、配置、资源合同或命令变化才更新 `README.md` 和相应权威文档。不把一次性结果追加进 `AGENTS.md`。
- 应用发布固定使用 `./scripts/deploy-prod.sh`。尽早用 `--check-hermes` 只读检查；本轮使用 `--wait-hermes` 在实际停服务前再次观察并等待自然结束。未知或失败不能当空闲，不取消任务；不改变普通部署路径。
- 不因本次前端/读取层治理重启 Hermes。若范围变化到跨端协议，停止扩大范围并确认。
- 发布前工作区不得有无关脏改、凭据、live 数据或边界不清的文件；部署保留既定生产数据库检查/快照与构建流程。
- 部署成功后、进入提交阶段前完成服务/健康/关键入口及适用性能复测，核对生产关键源码/资源与本地版本。失败停止提交推送，先保留证据、确认回滚。
- 回滚遵循部署手册：先回滚兼容代码，不默认回退数据库；不使用硬重置、不直接覆盖 live。数据库恢复或其他高风险覆盖必须说明精确对象并获确认。
- 整体治理使用一个语义完整的提交，包含本计划固定的大文件范围及完整变更文件清单。进入 ship(提交交付)阶段后只读 diff、写提交描述、commit、push；不再运行测试、构建或代码探查。最后核对本地与远端目标分支 SHA。
- 记录分析、开发、验证、等待、部署和提交的实测耗时，区分工具运行和模型响应，扣除并行重叠；不能复原的时间标为未计时，不估算成精确数字。
