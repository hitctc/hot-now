# 长短内容双线流程与复用优化计划

日期：2026-10-03。HotNow参考版本：`932fee5`；Hermes源码参考：`/Users/tc-nihao/.hermes`。本文是已实施阶段的历史计划与基线，不是当前待开发清单；落地证据见文末，现役合同以README和Hermes边界为准。后续短素材评分、短成品趋势移除、封面/正文分离及事实保护不由此处旧方案覆盖。

**方向已由用户确认：长文、短内容是两条业务线；流程不完全相同，复用共同能力；新短内容采用统一生成策略，不再按“贴图/反转文”二分。** 目标是形成可解释、可恢复、质量可靠且减少无效工作的完整体系，不只是改标签。

用户已授权按计划开发、验证、部署、提交推送，并授权自行确定统一规格及兼容方案。已落地双线最小实现，验证与发布状态见文末；不改依赖、历史数据库或模型/生图配置。现役边界以[Hermes自动化协作边界](./Hermes自动化协作边界.md)为准；短内容旧字段、展示、评分和兼容清单见[短内容专项计划](./短内容写作语义与展示治理计划.md)。

## 1. 成功标准与设计原则

1. 每条线从素材到成品都有清楚的阶段输入、产物、门禁、失败处理、恢复位置和责任模块。
2. 长文保留读者价值、证据骨架与深度表达；短内容保留事件复盘、有限判断与简洁表达。不把短内容做成长文压缩版。
3. 新短写只有一套内容策略；篇幅随素材复杂度变化，图片资产与文体解耦。历史form仍兼容，但不再决定新稿业务类型。
4. 共同能力复用已有模块；不建立万能流程引擎、第二队列或统一评分。两条业务编排仍分别清晰可读。
5. 附属文案、导语和图片提示词基于最终交付稿；失败/取消/恢复不会重复已完成模型请求、产生重复成品或覆盖新编辑。
6. 效率以模型请求、搜索/抓取、令牌、排队/执行/交付耗时和返工次数衡量；不以降低质检、缩减候选或丢功能换速度。

### 已发现的文档冲突与执行缺口

- Hermes `scripts/prd/公众号写作管线-任务与Skills协作索引.md`第5节第11项称自动不合格稿也交付审核；当前自动代码有限重写后停止，允许待审核交付的是人工路径。按代码裁决现状，实施时同步修正文档，不把文档冲突变成自动门禁变化。

## 3. 当前两条线：从准入到交付

### 3.1 长文现状

```text
来源采集/基础与趋势评分
  → 账号适配、普通人相关性与搜索意图
  → 自动计划/槽位授权；人工按现役入口处理
  → Hermes唯一队列
  → 1 现实证据包
  → 2 读者价值方案
  → 3 事实判断骨架与核心判断证据门禁
  → 4 口述底稿
  → 5 受限编辑＋human-writing审改＋文本卫生
  → 6 导语/摘要/制图标签＋标题候选和推荐
  → 7 图片提示词与按资格执行的图片路径
  → 8 拼装、平台交付与审计
  → 符合资格的自动Luna图片在同篇任务内完成闭环
```

账号适配与相关性是写前准备，不冒充文章正文阶段。人工不等待账号适配，不按自动低适配门槛拦截。长文标题失败的严格处理、核心判断证据门禁不因复用而放宽。

长文“八阶段”是现役展示口径；Luna后续闭环会报告图片进度。不能据八阶段结束、已有文章编号或提示词存在，就宣称自动图片任务全部成功。

### 3.2 短内容现状

```text
热搜采集/跨平台去重/素材同步
  → 选题价值评分＋判断方向参考＋suggested_form
  → 当前批次平台轮转候选与逐篇投递
  → Hermes唯一队列（人工入口另有优先级）
  → 补事件上下文
  → auto选择或显式form选择两套正文规格
  → 正文/新标题/标签＋评论/作者拓展
  → 初检；自动失败反馈重写，人工按现役规则留审核稿
  → 合格稿human-writing＋复检＋文本卫生与复核
  → 终稿导语
  → 本地保存、图片提示词、定向交付
  → 自动定向交付后代码制图；人工按原显式操作
```

补上下文当前用摘要打底、搜索并读取页面，失败可退回已有摘要；不是长文的结构化证据包门禁。短写标题与正文一起生成，缺失或事实校验失败再补写；不是长文分组标题方案。

HotNow空白人工新建是第三种入口，但不是第三条模型写作业务线：只保存草稿，不调用Hermes。历史补推、独立CLI及旧 `/api/short/regen` 也不能冒充现役新写主链；后者的消费者未确认，不直接删除或宣称已迁移。

## 4. 目标体系：双线编排，共同底座

```text
             共同底座（复用已有能力）
   模型调用/搜索读取/唯一队列/检查点/审改/资产/交付适配
                       │
       ┌───────────────┴────────────────┐
       │                                │
   长文业务编排                     短内容业务编排
   深度证据与读者任务               事件事实与有限判断
   价值方案→骨架→底稿               轻量事实整理→统一短写
   长文编辑和标题策略               短稿质检/有限重写/标题保真
       │                                │
       └─────终稿确认→各自资产策略→交付────┘
                     HotNow保存/编辑/展示
```

这是职责图，不是新服务、新目录或新调度器设计。复用以真实函数职责为边界；先使用现有模块，只在合同相同且重复已被证实时做最小提取。

### 4.1 长文目标：保持业务，补齐边界

- 保留现役八阶段及其准入、证据、编辑、标题、图片资格。
- 重点核对阶段内部成功产物复用、发布资产依赖、平台交付后的图片续跑和错误归因。
- 只有重现测试或计数证据证明重复/错位时才改，不借本轮重做长文架构、模型或写作策略。

### 4.2 短内容目标：统一策略，终稿驱动资产

以下是逻辑分段，不是新增API、数据库状态或强行改现役trace编号：

| 逻辑分段 | 输入与产物 | 门禁/失败/恢复要求 |
| --- | --- | --- |
| 准入与投递 | 当批素材、选题分、判断参考；形成候选/受理编号 | 保持平台轮转、逐篇节奏、人工优先和请求重放；判断参考不是必须照写的结论 |
| 事实准备 | 原标题、摘要/全文、可追溯来源、已知事实与未知项 | 复用搜索读取能力，不强行复用长文全套证据模型；事实不足不得编造，新增停止门槛须另行确认 |
| 统一写作 | 单套提示词生成新标题、正文及可同请求产出的标签 | 新任务不消费form选分支；篇幅按信息量变化；标题事实与原创表达按现役规则检查 |
| 质检与终稿确认 | 初稿→初检→必要反馈重写→审改/复检→文本卫生 | 自动/人工各自策略保持；锁定最终标题/正文及对应质检，不把失败候选当终稿 |
| 发布与附属资产 | 终稿→导语、评论、作者拓展、标签/图片提示词 | 移除初稿阶段的评论/拓展生成，按原功能与数量在终稿后生成；不静默改成仅人工生成 |
| 保存与交付 | 对应同一终稿的正文、分数、资产、来源与轻量审计 | 延续本地保存/平台关联/定向交付；失败只恢复未完成段，不生成第二篇或重复代码制图 |

手动未合格稿仍按既有合同交付审核，不冒称“已过终稿质检”；它的附属文案应对应实际交付的审核稿。移到后段不等于禁止人工审核稿拥有原有功能。

标题、标签或正文如在审改后变化，必须核对已有附属资产是否仍对应终稿；例如正文阶段已返回标签，不意味着终稿修改后它仍有效。优先本地检查或放入已有后段请求，不为了补标签无条件新增模型请求。

| 能力 | 可复用部分 | 必须分别保留的部分 |
| --- | --- | --- |

| 终稿审改 | `human_writing_review`、版本指纹、追踪字段、事实锁定工具 | `review_long_content`与`review_short_content`不同校验；短稿质检/回退 |
| 标题/发布文案 | 事实校验、标签规范化、已有纯生成工具 | 长文分组推荐与严格失败；短稿原标题保真、新表达和补写 |

| 恢复/交付 | 唯一队列、受理收据、成功调用、编号关联与版本控制 | 各线阶段产物、阈值、自动/人工终态和旧任务合同 |
| HotNow界面 | 成品查询、详情、编辑、保存、资产操作能力 | 长短独立列表/入口与实际业务说明；不增加旧文体推断 |

不能把模块都“抽公共”当作成果：只有两边调用合同一致、副作用清楚、测试证明行为保持的重复实现才提取。不建通用工作流配置语言或层层包装。

## 5. 统一短写的兼容与待定规格

### 已确定

- 新短写不按tuwen/duanwen分两套正文策略，不再模型判断旧form；选题价值与图片资格不依赖旧文体。
- 不删schema字段，不批量重标、重写或重算历史，不修改持久任务标签。
- 历史form不用于表格业务分类、图片有无或评分版本推断；成品质检与素材趋势分别展示。
- 图片提示词、实际图片、代码图片和封面分别处理；统一短写不授权增加自动生图。

### 已锁定并实现的规格

1. **正文/加粗约束**：统一建议120–600字、1–4处重点，按信息量表达；沿用原正文解析/质检，不新增硬性字数门禁。审改与卫生校验采用统一重点范围，旧任务原范围不变。
2. **附属资产预算**：评论/作者拓展保留，基于实际交付稿最多3000字符；图片提示词1条，代码图三比例和实际生图许可不变。标签缺失或终稿改变导致失效时再生成，失败不伪造；检查点I/O失败须停止后续调用。
3. **旧显式请求**：新默认/auto映射统一策略；显式tuwen/duanwen保留原规格。界面仅发auto，不再提供业务二分。原枚举/URL/权限保持，人工空白新建允许省略form，非法显式值仍拒绝。
4. **识别新旧执行**：利用已核实的队列kwargs保存内部 `writing_strategy=brief-v1`；无参数旧任务沿原默认恢复。写作trace记录 `writingStrategy`，不用日期/form猜版本，不新增schema或对外策略参数。
5. **技术失败处理**：新短写技术错误交现有一次恢复预算，内容不合格仍最多重写2次。回推失败复用成功产物和本地编号，已有平台关联不再重推或制图；旧无标记任务保留原终态合同。

已受理或正在运行的旧任务冻结原输入、策略和检查点，不能在恢复途中切换提示词或校验。新任务才使用统一策略。兼容请求不应成为新业务分类；旧独立调用须确认消费者后再迁移。

是否增加任何持久字段/迁移，必须先证明现有元数据不足并给出最小方案；不以本计划为新增schema的自动授权。

## 6. 效率治理：先计数，后优化

### 已有能力，不能重复建设

- 长文阶段检查点、短写按输入保存的调用检查点，以及共享Codex同输入成功返回复用。
- 原始素材摘要打底；长文准入搜索意图可传给资源包；不重复生成搜索意图只因进入另一模块。
- 既有唯一队列、冷却归队、人工让位、请求编号与图片子阶段恢复。
- 长文导语/摘要请求已合并制图标签；不能再额外新建“全文章标签阶段”。

### 优化候选与证据要求

| 候选 | 当前证据/风险 | 开发与验证边界 |
| --- | --- | --- |
| 评论/拓展移到终稿后 | 短写当前先生成，后续正文可重写/审改 | 用调用顺序、正文版本和请求计数证明不为弃稿生成；保持最终功能/失败降级 |
| 去掉新任务form判定与分支 | auto优先建议，缺失才多一次模型判形态 | 仅无建议场景可声称少一次判定调用；全部新稿走统一策略，旧任务恢复保持 |
| 复检按实际输入复用 | 现有指纹已经复用完全相同输入 | 保持所有改变正文后的必要质检；确认不变输入及质量规则/上下文一致才能复用，不能直接删复检 |
| 搜索/事实准备复用 | 两线都用搜索读取，但证据结构/新鲜度不同 | 先测同任务重复；默认仅复用本任务已成功产物，不跨线跨任务共享旧证据缓存 |
| 阶段内部复用 | Codex已有底层复用，其他提供方与副作用需核对 | 注入子步骤失败测模型/搜索/入库计数，不假定所有提供方相同、不擅自切模型 |
| 成品交付恢复 | 已有本地稿与平台冲突编号恢复 | 回推失败只续交付；图片失败只续图片；故障注入后正文模型计数不得增加 |
| 附属资产请求合并 | 有不同提示词、失败降级和预算 | 只在测量后比较，不能为少一次请求合并质检/审改或降低任一子结果校验 |
| 文案/显示纠偏 | form、爆文、趋势来源混用 | 不加推断分类请求，不增加列表逐行详情或新轮询，保持前轮性能成果 |

不新增常驻遥测、跨任务缓存、并行模型调用、独立worker或图片补图队列。跨任务证据共享、独立并发或降级变更是新需求，不在当前最小实现里。

### 验证指标
